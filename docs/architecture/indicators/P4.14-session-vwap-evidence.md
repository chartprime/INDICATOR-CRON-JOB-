# Session VWAP (P4.14)

> **Historical implementation evidence.** This dated page records the result
> of a completed build. It is not a current deployment/health statement; use
> the [final-state indicator index](README.md) and the handbook for supported
> operation.

Session VWAP is an **overlay reference line**: the volume-weighted average
price of the volume traded since the current session opened, with
volume-weighted deviation bands, drawn as one segment per session window. It
describes where volume has traded; it is not a signal, an entry level or a
forecast.

It is registered as `sessionVwap` (`kind: "runtime"`, category `technical`), with the
line keys `vwap`, `upper1`, `lower1`, `upper2` and `lower2` on the price pane. It
owns the **blue** family — the average and inner band solid and the outer band at
80 % — against [VWAP Bands](P4.15-vwap-bands-evidence.md)'s violet average and
fuchsia deviations, so the two can be told apart when both are on the chart.

## Two anchors: the session, or a window anchored N bars back

Session VWAP offers the same **Anchor** dropdown as
[VWAP Bands](P4.15-vwap-bands-evidence.md), and this module owns that choice — the
options, the bounds, the settings fields and the rule that finds the anchor — so
both indicators mean the same thing by "lookback":

| Anchor | Window | Its own input |
| --- | --- | --- |
| Session VWAP (default) | the current session window | Session length |
| Lookback VWAP | the bars from N bars back from the newest bar up to it, 300 by default | Lookback (bars), a slider from 10 to 500 |

The lookback window needs no session concept at all. It is **a bar, not a period**:
the anchor is the `lookbackBars`-th bar back from the newest bar of the series
being fed, which only the series itself can say, so the runtime hands the
indicator its position in that series (`ctx.barIndex` / `ctx.barCount`) and the
anchor is decided on the replay that establishes the window. It then **stays put**
while bars arrive and the window develops from there to the newest bar, so nothing
falls out of it — anchored, not rolling. If the chart holds fewer bars than the
lookback, the window starts on the first bar it is given.

Nothing is drawn before the anchor, a bar inside the window that traded nothing
adds nothing (the average carries flat, as always), and nothing is painted
transparent in lookback mode: the join rule below exists to stop two *sessions*
being read as one line, and an anchored window has no boundaries to join.

## Sessions are the session profile's own windows

The windows are the same UTC-aligned fixed periods Session Delta Profile
draws, from the same list of session lengths (1 Hour … 1 Week), resolved with
the same rule as `ChartPanel.tsx`'s `applySessionDeltaProfileVisibility`:

```text
sessionStartTs = floor(ts_open / sessionPeriodMs) * sessionPeriodMs
```

A bar belongs to exactly one window (`ts_open >= start && ts_open < end`), so a
VWAP segment lines up with the session profile zone drawn beside it for the
same length. Fixing that rule once, rather than inventing a second session
concept, is why the two agree.

## The segment that would join two sessions is never drawn

The library paints each segment with the colour of the point it **starts** from:
`PaneRendererLine._internal__strokeStyle` returns `item._internal_lineColor`, and
`walkLine` only calls `changeStyle` *after* the segment ending at that item has
been stroked. The bar that therefore controls the segment joining one session's
average to the next's is the **last bar of the session** — the bar that walks up
to the window's end (`ts_open + interval_ms >= sessionEnd`) — and that bar is
painted fully transparent.

Everything stays plotted: only that one colour changes, so a session starts on
its own first bar rather than one bar late, and both the VWAP line and every band
stop and restart cleanly instead of jumping.

Two things this rules out, both measured against the library rather than assumed:

- **A null value does not work.** A whitespace entry is not a value row
  (`getSeriesPlotRow` returns a row without `_internal_value`, and the series'
  rows are filtered by `isSeriesPlotRow`), so the two neighbouring points simply
  become adjacent and the line is drawn straight through them. The steep join
  survives, which is how this was found.
- **A transparent point *after* the join does not work either**, for the same
  colour-direction reason: hiding the new session's first bar would hide the
  segment leaving *it*, and leave the join itself visible.

Two invisible colours are kept apart on purpose — one for a band switched off (a
setting) and one for a session join (history) — because `recolor` is handed a
stored string and no bar, and must not confuse them: if it did, toggling a band
would resurrect every hidden join.

A bar longer than the session cannot resolve a boundary, so nothing is hidden in
that case rather than blanking the whole line.

## The source is the bar, and only the bar

Each bar contributes its own traded volume at its typical price
`(high + low + close) / 3`:

```text
VWAP = Σ(v·TP) / Σv
σ    = sqrt( Σ(v·TP²) / Σv − VWAP² )
```

- The **volume** is the venue's own traded volume for that candle — exact, in
  Live and Historical Mode, on every instrument and every timeframe, with no
  tick, order-book, storage or host dependency. It is never estimated.
- The **price inside the bar** is the estimate, and it is the only one in the
  indicator. A candle does not say where inside itself the volume traded.

Two consequences are accepted deliberately:

1. **The bands read narrow.** `σ` is a dispersion measure, and collapsing a bar
   to a single price cannot see the dispersion inside it, so `upper1`/`lower1`
   and `upper2`/`lower2` are tighter than a tick-derived measurement would give
   — the more so the longer the timeframe. On a 1-minute chart this is small;
   on a 1D chart it is material.
2. **No tick source is carried.** Tick-derived volume-at-price would remove that
   estimate: the L2 grid's per-row aggressive print flow arrives on connect, the
   host's `band_history` covers any past range, and the archive's profile study
   covers Historical Mode. All three are per-price-bucketed trade volume, which
   is what this indicator would use if the bands ever need to be exact. None is
   wired here — the bar source is the whole of this build.

   The print-priced variant exists as its own indicator instead, so this one
   stays bar-exact in every mode: [VWAP Bands](P4.15-vwap-bands-evidence.md) in
   the `l1` category prices these same session windows from the terminal's L1
   print store (or a window anchored N bars back from the newest bar, when its
   Anchor says so), carries no bar fallback of any kind, and is therefore not
   offered in Historical Mode at all.

## How a tick-sourced VWAP is normally built

The published ProVWAP+ study (Tradovate community) uses the **bar's volume
profile** — trade size per price level inside the bar — and only falls back to
bar volume × a representative price when no profile is available. It keeps the
same math as this one (`Σpv/Σv`, `σ² = max(Σp²v/Σv − VWAP², 0)`, `VWAP ± kσ`),
caps the fallback's quality honestly, and colours the line by which source drew
it, so an approximated bar is never mistaken for a tick-true one.

That is the blueprint if this indicator ever needs exact bands:

- the per-price trade volume already exists in this repo — the L2 grid's
  aggressive print flow (`ctx.liquidity`), the host's `band_history`, or the
  archive's `profile` study, all bucketed by price row;
- the bar approximation stays as the fallback so the pane is never blank;
- the colour channel can mark a fallback bar, exactly as the band and
  session-join colours are already used here;
- its other knobs are worth copying when the need appears: a choice of typical
  price vs close inside the bar, more than two band widths, and a rolling
  (N-bar) mode beside the session-anchored one this implements.

The alternative that was tried and then removed (2026-09-30) wired two of them
in: it made the line depend on the L2 grid, the live tape and a coverage rule,
for a difference that shows up in the bands rather than in the line. The bar
source draws the same line in every mode with none of that.

## Deviations and bookkeeping

σ is evaluated from the running sums (`Σv`, `Σvp²`, `ΣvTP`) as
`sqrt(ΣvTP²/Σv − VWAP²)`, so no price history has to be retained; negative
rounding noise clamps to zero. The two band widths are ordered and clamped
(`normalizedBandSigmas`), so the inner band can never sit outside the outer one
and a crossed pair mid-edit cannot invert the lines.

A `REPLACED_EDGE` re-delivers the developing bar with its updated numbers, so
the bar's earlier contribution is subtracted before the new one is measured — a
bar that updates many times before it closes is counted once, and a withheld
boundary stays withheld through those updates. A bar that traded nothing adds
nothing, so the session keeps its running average (a flat step) rather than
punching a hole in the line.

Identical prices give σ = 0 and both bands collapse onto the VWAP.

## Settings

| Setting | Tab | Effect |
| --- | --- | --- |
| Anchor | Inputs | Recompute. Switches between the session window and the anchored lookback, replaying the bars to rebuild whichever window it needs. |
| Session length | Inputs | Recompute. Replays every bar, rebuilding each session. Hidden while the lookback anchor is selected. |
| Lookback (bars) | Inputs | Recompute. Re-anchors the window and rebuilds it. Slider, 10–500 bars, default 300. Hidden while the session anchor is selected. |
| Inner / outer band (σ) | Inputs | Recompute. Resizes the whole distribution, so it replays the bars. |
| Show deviation bands | Visibility | Cosmetic. Paints the band series transparent rather than deleting it, so toggling never replays anything. |
| VWAP / band colors | Visibility | Cosmetic. Recolored in place; a hidden session join stays hidden. |

Every line carries a `recolor`, so a purely cosmetic edit takes the cheap
recolor path instead of a full replay.

There is deliberately **no "sessions shown" setting**: the numeric line channel
emits one point per bar and cannot retract a point it has already emitted, so a
segment already drawn stays on the chart whatever such a control said. What
exists instead is a fixed memory bound, `SESSION_VWAP_RETAINED_SESSIONS` (8):
only the newest few session accumulators are kept. Nothing older can lose a
value it would otherwise have had, because a session's bars are all processed
while it is the newest window.

## Known limits

- The price inside a bar is an estimate, so a long timeframe (1D) is much
  rougher than 1m, and the bands read narrow because a candle cannot show its
  own internal dispersion.
- The join is hidden only when the session's last bar is a bar of the chart. A
  bar longer than the session cannot resolve a boundary, and a window whose last
  bar is missing from the data (a market that closed before the window ended)
  keeps its segment as it is.
- The chart's own bar retention decides how far back sessions are drawn; the
  indicator keeps the newest 8 session accumulators for its own bookkeeping.
