## 3. Polling design per family

**Trades (`/api/v3/aggTrades`, weight 4).** The WS path emits one envelope per `@trade` message (`binance-connection.js:76`), normalized from keys `t,p,q,T,m` (`normalizer :21, :42, :318-325`, event time `T` :297), and downstream derives side as `isBuyerMaker ? "sell" : "buy"` (`frames.js:163`, `l2-memory/live-binding.js:52`) and dedupes by `trade_id` (`server/history.js:206-214`). Pager: on subscribe, `GET aggTrades?symbol&limit=1` sets `cursor = a`. Each tick: `GET aggTrades?symbol&fromId=cursor+1&limit=1000`; while a page is full, fetch the next at once (cap 5 pages per tick, then `feedHealth.beginRecovery(TRADE)` and continue next tick, never drop). Aggregate ids are contiguous: a row with `a <= cursor` is dropped as a duplicate; a jump is telemetry `market_data.binance_rest.trade_id_gap`, never filled. Each row becomes raw `{e:"trade", E: receivedAtMs, s, t: a, p, q, T, m, M}` for `normalizeBinanceEvent`: `payload.tradeId` is the aggregate id, `eventTime` the exchange time `T`, emission order `a` ascending.

**Bars (`/api/v3/klines`, weight 1 for limit ≤ 100).** Today 1m bars come from the `@kline_1m` stream, not from trades (`market-data-server.js:119, :1248-1249`; `klineEnvelopeToFrame` `frames.js:168-210`, closed from `k.x`); backfill uses REST rows (`restKlineRowToBarFrame` `frames.js:212-263`). Each tick: `GET klines?symbol&interval=1m&startTime=<previous minute open>&limit=2`. Row 0 is emitted `x:true` once per `openTime`, only after `closeTime < receivedAtMs`; row 1 `x:false` whenever `c,v,n` changed. Raw: `{e:"kline", E: receivedAtMs, s, k:{t,T,s,i:"1m",o,c,h,l,v,n,x,q,V,Q}}`; `f`,`L`,`B` are optional (`normalizer :24, :48-64`). `fetchRecentKlines` delegates to the existing backfill.

**Depth (`/api/v3/depth?limit=1000`, weight 50) as periodic snapshots.** The assembler needs a snapshot and then a bridging diff: `applySnapshotStatus` sets `needsBridgeCheck = true` (`binance-book-assembler.js:352`) and `getStatus` stays `BUFFERING` until a diff with `U <= lastUpdateId+1` arrives (:85-105, :264-288, :381-398). A snapshot-only feed never leaves BUFFERING, so add one explicit method, `applyStandaloneSnapshotStatus(body)`: the same validation (`snapshotDepthBody` :27-43, crossed book :339-344, level cap), then `needsBridgeCheck = false`, `localUpdateId = body.lastUpdateId`, buffer cleared. No synthetic update ids. The transport keeps one real assembler per pair and feeds it every poll, so `getOrderBook` returns a READY book whose `lastUpdateId` is the snapshot's own id (`emitBook` fingerprints on it, `market-data-server.js:963-968`).

For the L2 engine the transport emits one DEPTH envelope per snapshot: `firstUpdateId = lastUpdateId = snapshot.lastUpdateId`, `previousUpdateId: null` (SPOT, `normalizer :364-367`, `assembler :69-71`) and `bids`/`asks` = the observed level changes between the previous and current snapshot, computed only inside the price window both snapshots cover (bids `>= max(oldLowestBid, newLowestBid)`, asks mirrored); a vanished level is reported with quantity `"0"` as Binance does; levels that merely left the 1000-level window are not reported. `live-binding.js:44-47` makes a `book` frame whose `delta` is those changes; `memory-engine.js:201-250` applies it as a diff while `live`, seeds on the first READY book (:131-141), resyncs after a gap (:143-158), and `coverageOf` (:106-114) reads the real edge of the 1000-level book. A failed poll emits nothing; `429/418` or three consecutive failures mark DEPTH recovering, the `gateBookState` equivalent returns `UNAVAILABLE: RECOVERY_IN_PROGRESS` and `live-binding.js:45` sends a `gap` frame, as a WS sequence gap does (`binance-connection.js:1377-1390`). The periodic and shadow refreshes (:65, :867-886, :1580-1641) do not apply.

## 4. Honesty

- `getStatus()` reports `SPOT.public` `CONNECTED` only after a successful `exchangeInfo?symbol=BTCUSDT` probe (weight 20, `fetchExchangeInfo` :303-319), `DISCONNECTED` after three consecutive failures; PERPETUAL routes stay `DISCONNECTED`, so a perpetual `subscribeMany` throws today's "route is connected" error (`binance-connection.js:1004-1016`) and `requestSwitch` parks the selection (`market-data-server.js:3496-3508`).
- `getFeedHealth()` returns the feed-health context plus `transport: "rest"`, `pollMs`, `lastPollLatencyMs` and `reason`: `REST_POLL` while READY, `REST_RATE_LIMITED`, `REST_POLL_FAILED`, `REST_BACKOFF_<ms>` while degraded. `market-data-server.js:845-856` passes the worst context's `reason` to `healthFrame` (`frames.js:663-694` accepts a reason with READY, limit 256 chars :28); the browser already prints it (`apps/web/src/components/chart/MainPanel.tsx:2436`). The health fingerprint includes it (`market-data-server.js:944`), so every change is broadcast.
- Staleness keeps today's thresholds (`binance-feed-health.js:7-12`: TRADE 30 s, KLINE 10 s, DEPTH 5 s). A successful empty trade poll is a real observation and records `recordEvent(TRADE)`; a failed poll records nothing, so silence becomes `stale: true` as with a dead stream. No envelope is ever emitted without a row.
- Backoff: on `RATE_LIMITED` (`binance-http-client.js:231-234` parses `Retry-After`) every family of every pair pauses until the later of `Retry-After` and exponential backoff (1 s base, 30 s cap, 20% jitter, as `binance-connection.js:47-49, :1704-1740`), with `beginRecovery` on all families and telemetry `market_data.binance_rest.backoff`. A `418` (IP ban) waits the full `Retry-After` and sets `DISCONNECTED`.
- Weight accounting: every response's `x-mbx-used-weight-1m` (already in `result.value.headers`) is authoritative; the budget module also projects per calendar minute: aggTrades 4 per page, klines 1, depth 50 (limit 1000), exchangeInfo 20, kline backfill 5 per 1000-row page. With one pair at `pollMs=1000`: 60·(4+1) + 60·50 = 3300/min ≤ 4000, so depth polls every tick. The scheduler stretches the depth cadence first (to the smallest multiple of `pollMs` that fits), then klines, never trades; two pairs: 600 + 3000 (depth every 2 s) = 3600. If the header reaches the budget, all polling stops until the minute boundary; the hard limit 6000 is never approached (margin ≥ 2000).

## 5. Proxy support

It ignores `HTTPS_PROXY` unless `NODE_USE_ENV_PROXY=1` (Node ≥ 22.21; the repo pins 24.21.0, `package.json:6-7`). ## 8. Risks and what is not supported

- Not supported: perpetuals (no mirror; routes stay DISCONNECTED); sub-second latency (trades arrive up to `pollMs` plus round trip late; the engine's late-trade rule, `memory-engine.js:83-94`, keeps order); order-book diffs (a 1000-level snapshot at most once per tick; iceberg and exhaustion engines see coarser deltas, to be documented as degraded on REST); bookTicker; switching transport at runtime (aggregate and raw trade ids differ).
- Risks: endpoint weights may change (the header is authoritative, the ledger a projection); the mirror's lag behind the primary is undocumented (measure `T` versus `receivedAt` in the acceptance run); a 1000-level book is shallower than the 5000-level WS snapshot, so lane-0 heatmap coverage (±5%) may be partial on volatile days, with `coverageOf` marking the real edge.

# Data for indicator authors

[Handbook](../../README.md) · [Indicator index](README.md) ·
[Onboarding](../../operations/00-developer-onboarding.md) ·
[Indicator SDK](../indicator-sdk/TA.01-indicator-authoring-core-evidence.md)

An indicator never opens SQLite, S3 or a provider connection itself. It reads
what the runtime and the archive deliver through a small number of supported
boundaries. This page names those boundaries, says what each one carries for
each instrument, and lists the rules every indicator has to follow. The code
named here is the authority; when this page and the code disagree, the code
wins and this page is the defect.

## Three sources of data

| Source | How it reaches an indicator | You need | When it is missing |
|---|---|---|---|
| **Live ticks** | Terminal C holds the provider session and sends canonical frames (`bar`, `trade`, `book`, `health`, profiles, VPIN readings) over the local `/ws` WebSocket | Binance: nothing. dxFeed: layer 2 (Tailscale broker) | dxFeed instruments show *History only*: with layer 1 their recorded host history still loads, without new ticks |
| **Warm-up** | Before live ticks arrive, the runtime reads recent history through its storage reader: candles, large trades, aggressive prints, volume profile, VPIN calibration | Layer 1 (WireGuard + bearer); otherwise only a local collector's SQLite | The indicator starts from live ticks only and reports itself not ready |
| **Archive** | Historical Mode reads candles through `/archive/query` and asks the host for four studies through `/archive/study` | Layer 1 | Historical Mode shows *Historical Mode needs host data access* |

The three layers are explained in [onboarding](../../operations/00-developer-onboarding.md);
`npm run doctor` reports which ones a machine has.

Warm-up and live ticks meet in the runtime; the archive is a separate path used
only by Historical Mode. A successful warm-up does not prove an archive
partition exists, and an archive answer says nothing about the live collector
today.

Live Mode also has a bounded `band_history` request for a historical price band.
The laptop sends the instrument, price range and time window through Terminal C;
the host replays its recorded raw depth and returns resting size and traded
flow per row. Institutional Order Blocks v1 reads a block the visible live
history did not cover from the host's stored heatmap columns first
(`/heatmap/columns`, cut to the block's rows in the browser) and uses
`band_history` only when the host has no stored columns for the pair or that
read fails. Session Levels reads a touched level's five minutes and a range's
totals from the same stored columns, with no raw-replay fallback. A missing book interval remains a gap, never a
zero-liquidity observation. Each host read is capped at two hours, 256 rows and
100,000 row/column cells; the client pieces longer requests. This is an
on-demand derivation, **not a stored canonical L2 row dataset**, and it does
not make order-book indicators available in the separate Historical Mode
archive. See the [wire contract](../../contracts/ws-frame-contract/v1/ws-frame-contract-v1.md)
and `apps/runtime/src/server/band-history.js` for the exact boundary.

## What each instrument has

| Instrument | Live ticks | Warm-up from the host | Historical candles | Historical studies |
|---|---|---|---|---|
| BTC, ETH spot and perpetual (Binance) | always | yes | 1m, 1h, 1d, each with taker buy volume | none yet |
| ES, NQ (continuous futures) | with layer 2 | yes, what the weekday collector captured | 1m, 1h, 1d | profile, VPIN, large prints, bar flow |
| AAPL, TSLA (equities) | with layer 2 | yes, what the weekday collector captured | 1m, 1h, 1d | profile, VPIN, large prints, bar flow |
| NVDA (equity) | with layer 2 | yes, what the weekday collector captured | not archived | none |

**Equity candles are regular session only**, live and historical alike:
09:30–16:00 New York time, with the exchange's holidays and early closes from
[`config/market-calendar.json`](../../../config/market-calendar.json). Hourly
bars start at 09:30, the last one ends at the bell, and a daily bar is that
session. Pre-market and after-hours prints are not in equity candles. Futures
and crypto candles are UTC-aligned and cover every traded minute.

Other timeframes are resampled in the browser from those rungs. The governed
instrument list, exact provider symbols and tick sizes live in
[`config/market-instruments.json`](../../../config/market-instruments.json);
the archive's list lives in `apps/web/src/lib/archive/historicalCatalog.ts`.

The four studies are computed on the host from trade-derived families, so the
browser never pages minute rows. Their request, limits and refusals are in the
[archive study contract](../../contracts/archive-study/v1/archive-study-v1.md).
In short: a profile per requested range, VPIN over whole UTC weeks (at most 26),
and large prints and bar flow over one bar-aligned range of at most 5,000 bars.

## Which indicators work in Historical Mode

`HISTORICAL_INDICATOR_POLICIES` in `apps/web/src/lib/chart/indicatorRegistry.ts`
decides this, per indicator, from the capabilities the selected archive
provides. There are three policies:

| Policy | Needs | Works on |
|---|---|---|
| Candles | `ohlcv` | every archived instrument |
| Candle flow | `ohlcv` + `buy_volume` | Binance (candles carry taker buy volume) and ES/NQ/AAPL/TSLA (the `bar_flow` study supplies both sides) |
| Trade families | `ohlcv` + `trade_families` | ES/NQ/AAPL/TSLA |

An indicator can also be marked unavailable with a reason, as order-book and
every-trade indicators are: the archive has no historical depth and keeps only
the largest prints of each minute.

## Rules every indicator follows

**Read buy and sell through `barSides`.** Never compute sell volume as
`volume - buy_volume`. `apps/web/src/lib/indicators/barSides.ts` returns
`{known, buy, sell, unknown, delta, sided}` for a bar. It uses an explicit
`sell_volume` when the bar has one, and falls back to `volume - buy_volume`
only for bars that carry just a buy side. That fallback is exact for Binance,
where every trade has a taker side. It is not exact for equities.

**Unsided volume is real and large for equities.** A Databento equity trade
often has no aggressor side. Measured on the host (Report 54): ES and NQ are
effectively fully sided, but AAPL is about 40% unsided on one-minute bars and
65–75% on hourly and daily bars; TSLA is 35–55%. Historical bars carry that
volume separately as `unknown`, and `unsidedShare(bars)` gives the share to
show beside an equity delta. Counting it as selling would make every equity
delta read bearish by that amount.

Live dxFeed bars built from the tape carry buy and sell only when every trade in
that minute had a side. A minute with any unsided trade carries neither, so
`barSides` reports it unknown and it draws no delta, which is common for
equities. Stored native dxFeed candles carry both sides explicitly (volume at
the ask and at the bid), with any remainder unknown.

**`missing` is not `empty`.** A study reports ranges it could not read as
`missing`; draw them as unavailable, never as zero. It reports ranges it read
and found no trades in (a weekend, an overnight hour for an equity) as `empty`,
and those legitimately have nothing to draw. A bar with no trades is absent
from `bar_flow`; draw no delta for it, not a zero delta.

**Gate on capabilities, not on provider names.** Declare what the indicator
needs through its `HISTORICAL_INDICATOR_POLICIES` entry. Do not branch on
`provider === "BINANCE"`. The map is typed over every indicator id, so a new
indicator does not compile until it has a policy.

**Warm-up failure is not an empty signal.** When the storage reader cannot
reach the host it reports the read as unavailable. Show the indicator as
warming up or degraded, never as a flat or zero reading.

**Quantities are provider units.** Futures sizes are contracts, equity sizes
are shares, Binance sizes are the base asset. Do not add them across providers
or convert them to a notional the provider did not report.

**Need a new trade-derived aggregate?** Do not fetch minute rows into the
browser. A new study is a change to the archive study contract and the host,
and goes through the owner.

## Adding an indicator that works in both modes

1. Create `apps/web/src/lib/indicators/<name>/`. The folder owns the whole
   indicator: computation, geometry, primitive and settings. Follow the
   [SDK execution model](../indicator-sdk/TA.01-indicator-authoring-core-evidence.md).
   Its settings dialog gets [setting presets](setting-presets.md): a
   `settingsSchema` is enough for the generic dialog, and a hand-built one
   declares a preset schema for every setting it stores.
   Keep at most three primary controls on the Inputs tab and give every other
   input `tab: "advanced"`, which the generic dialog renders as a collapsed
   Advanced group.
2. Register it in `INDICATOR_REGISTRY` and give it a
   `HISTORICAL_INDICATOR_POLICIES` entry that names what it needs.
3. Read sides through `barSides`. For example, a cumulative delta that leaves
   bars without a known side undrawn:

   ```ts
   import type { BarFrame } from "../../../types/frames";
   import { barSides } from "../barSides";

   export function cumulativeDelta(bars: readonly BarFrame[]): (number | null)[] {
     let total = 0;
     return bars.map((bar) => {
       const sides = barSides(bar);
       if (!sides.known) return null;
       total += sides.delta;
       return total;
     });
   }
   ```

4. Check it in Live Mode on Binance (every machine can), then in Historical
   Mode on BTC and on one futures and one equity instrument (layer 1). On AAPL,
   confirm the unsided share is shown and the delta is not skewed.
5. Add tests for the computation, lifecycle, capability gating and rendering,
   as listed under *Adding or changing an indicator* in the
   [indicator index](README.md).

  if (!(price > 0) || !(tickSize > 0)) return DEFAULT_CLUSTER_TICKS;
  return Math.max(1, Math.round((price * bandBp) / 10_000 / tickSize));

function createLiveMemoryBinding({
  tickSizeResolver,
  clusterTicks = undefined,
  scales = scalesFromEnv(),
  debug = false,
  debugIntervalMs = DEFAULT_DEBUG_INTERVAL_MS,
  pruneIntervalMs = DEFAULT_PRUNE_INTERVAL_MS,
  log = (line) => console.log(line),
  ledgerOptions = ledgerOptionsFromEnv(),
  geometryFor = l2GeometryFor,
} = {}) {
  if (!tickSizeResolver || typeof tickSizeResolver.getBinanceTickSize !== "function") {
    throw new Error("live-binding: tickSizeResolver.getBinanceTickSize is required");
  }

  const quotes = new Map();
  const tickSizes = new Map();
  const readySeen = new Set();
  const resolving = new Map();
  const failed = new Map();
  let debugTimer = null;
  let started = false;

  function buildEngine(key, marketKind, symbol, tickSize) {
    const configured = typeof geometryFor === "function" ? geometryFor(marketKind, symbol) : null;
    const knownTicks = clusterTicks ?? configured?.clusterTicks;
    const knownSlice = ledgerOptions.minSliceSize ?? configured?.minSliceSize;
    const explicit = knownTicks !== undefined && knownSlice !== undefined;
    if (!explicit && !readySeen.has(key)) return null;
    const price = quotes.get(key) ?? null;
    const ticks = knownTicks ?? clusterTicksFor(price, tickSize, scales.bandBp);
    const minSliceSize = knownSlice ?? (price !== null ? scales.minSliceUsd / price : DEFAULT_MIN_SLICE_SIZE);
    const engine = createMemoryEngine({
      tickSize,
      clusterTicks: ticks,
      snapshotDepth: SNAPSHOT_DEPTH_BY_MARKET_KIND[marketKind] ?? Infinity,
      ledgerOptions: { ...ledgerOptions, minSliceSize },
    });
    if (debug) {
      log(`l2-memory: engine ready for ${key} (tick ${tickSize}, band ${tickSize * ticks}, dust floor ${minSliceSize.toPrecision(3)} base units${price !== null ? ` at ${price}` : ", no quote"})`);
    }
    return engine;
  }

  function createEngine(marketKind, symbol) {
    const key = pairKey(marketKind, symbol);
    const knownTick = tickSizes.get(key);
    if (knownTick !== undefined) return buildEngine(key, marketKind, symbol, knownTick);
    if (resolving.has(key)) return null;
    const lastFailure = failed.get(key);
    if (lastFailure !== undefined && Date.now() - lastFailure < TICK_RETRY_AFTER_MS) return null;
    const request = {};
    resolving.set(key, request);
    let lookup;
    try {
      lookup = tickSizeResolver.getBinanceTickSize(marketKind, symbol);
      if (!lookup || typeof lookup.then !== "function") throw new Error("live-binding: tick size resolver must return a Promise");
    } catch (error) {
      resolving.delete(key);
      throw error;
    }
    lookup
      .then((tickSize) => {
        if (binding.stopped || resolving.get(key) !== request) return;
        if (!Number.isFinite(tickSize) || tickSize <= 0) {
          failed.set(key, Date.now());
          return;
        }
        tickSizes.set(key, tickSize);
        failed.delete(key);
        binding.engineFor(marketKind, symbol);
      })
      .catch((error) => {
        if (binding.stopped || resolving.get(key) !== request) return;
        failed.set(key, Date.now());
        console.error("l2-memory: tick size lookup failed", key, error?.message ?? error);
      })
      .finally(() => {
        if (resolving.get(key) === request) resolving.delete(key);
      });
    return null;
  }

  const binding = createL2InputBinding({ createEngine, prune: { mode: "timer", everyMs: pruneIntervalMs } });

  function onDepth(envelope, bookState, fullBook = null) {
    if (binding.stopped || !envelope) return;
    const key = pairKey(envelope.marketKind, envelope.providerSymbol);
    if (bookState?.status === "READY") {
      readySeen.add(key);
      const bestBid = bestBidOf(bookState);
      if (bestBid !== null) quotes.set(key, bestBid);
    }
    const engine = binding.engineFor(envelope.marketKind, envelope.providerSymbol);
    if (!engine) return;
    let state = bookState;
    if (bookState?.status === "READY" && !bookState.book) {
      if (!engine.seeded || !engine.live) {
        state = typeof fullBook === "function" ? fullBook() : null;
      } else {
        state = { status: "READY", book: { bestBid: bookState.bestBid ?? null, bestAsk: bookState.bestAsk ?? null } };
      }
    }
    binding.apply(envelope.marketKind, envelope.providerSymbol, binanceDepthFrame(envelope, state));
  }

  function onTrade(envelope) {
    if (binding.stopped || !envelope) return;
    const frame = binanceTradeFrame(envelope);
    if (frame) binding.apply(envelope.marketKind, envelope.providerSymbol, frame);
  }

  function laneWindowPct(marketKind, symbol) {
    const configured = typeof geometryFor === "function" ? geometryFor(marketKind, symbol) : null;
    return configured && Number.isFinite(configured.windowPct) ? configured.windowPct : null;
  }

  function release(marketKind, symbol) {
    const key = pairKey(marketKind, symbol);
    binding.release(marketKind, symbol);
    tickSizes.delete(key);
    readySeen.delete(key);
    quotes.delete(key);
    resolving.delete(key);
    failed.delete(key);
  }

  function printDebug() {
    for (const [key, engine] of binding.entries()) {
      const s = engine.stats;
      log(`l2-memory ${key}: seeded=${engine.seeded} live=${engine.live} levels=${s.bidRecords}/${s.askRecords} deltas=${s.deltas} trades=${s.trades} late=${s.lateEvents} gaps=${s.unavailable} resyncs=${s.resyncs}`);
      if (!engine.seeded) continue;
      const far = engine.topLevels({ limit: 3 });
      log("  walls (largest anywhere):");
      for (const level of [...far.asks].reverse()) log(`    ask ${formatLevel(level)}`);
      for (const level of far.bids) log(`    bid ${formatLevel(level)}`);
      const snap = engine.snapshot();

      if (refPrice !== null) {
        const withinKeys = Math.max(1, Math.round((refPrice * 0.0025) / snap.clusterWidth));
        const near = engine.topLevels({ limit: 4, withinKeys });
        log(`  near book (within ${withinKeys} bands of best):`);
        for (const level of [...near.asks].reverse()) log(`    ask ${formatLevel(level)}`);
        for (const level of near.bids) log(`    bid ${formatLevel(level)}`);
      }
    }
  }

  function start() {
    if (started || binding.stopped) return;
    started = true;
    binding.start();
    if (debug) {
      debugTimer = setInterval(printDebug, debugIntervalMs);
      debugTimer.unref?.();
    }
  }

  function stop() {
    binding.stop();
    if (debugTimer) clearInterval(debugTimer);
    debugTimer = null;
    binding.clear();
  }

  return Object.freeze({ onDepth, onTrade, getEngine: binding.getEngine, laneWindowPct, release, start, stop, printDebug });
}

  const priceFor = (key) => key * clusterWidth;

  let live = false; // the diff stream is trusted: no gap since the last full book

  // would make a wall that has sat there for hours look newborn. Anything
  // outside the seeded range is therefore treated as pre-existing.
  let seededRange = { lowestBidKey: null, highestAskKey: null };

  // is stamped with the current clock instead of its own time; it then gets
  // netted against the *next* diff. Slightly late attribution beats a crash.
  function clock(ts) {
    if (ts < clockTs) {
      stats.lateEvents += 1;
      return clockTs;
    }
    clockTs = ts;
    return ts;
  }

    for (const [price] of tuples) {
      const key = keyFor(Number(price));
      sizeHistory.record({ ts, side, key, size: ledger.get(side, key)?.size ?? 0 });
    }

  // ends at index snapshotDepth - 1; anything the diffs added beyond that
  // (already present in this book, or arriving later) is outside it.
  function coverageOf(book) {
    if (fullDepth) return { lowestBidKey: null, highestAskKey: null }; // the book vouches for every price
    const edge = (levels) => {
      if (levels.length === 0) return null;
      const index = Math.min(levels.length, snapshotDepth) - 1;
      return keyFor(Number(levels[index][0]));
    };
    return { lowestBidKey: edge(book.bids), highestAskKey: edge(book.asks) };

    recordSizes(ts, "bid", book.bids);
    recordSizes(ts, "ask", book.asks);

    if (!book || !Array.isArray(book.bids) || !Array.isArray(book.asks)) {
      throw new Error(`memory-engine: a full book is required to ${purpose}, but this frame carries only its best prices`);
    }

        preexisting.push(tuple);
      } else {
        known.push(tuple);
      }

    }
    live = false;
  }

      stats.deltas += 1;

    ledger.observeQuote({ ts: now, ...best });
    flow.addQuote({ ts: now, ...best });

    pendingPrints = [];

function createBinanceFeedHealthMonitor({ now = () => Date.now() } = {}) {
  const lastReceivedAtMs = new Map();
  const connectedRoutes = new Set();
  const recoveryStartedAtMs = new Map();

  function recordEvent(marketKind, symbol, eventType, interval, receivedAtMs) {
    const key = eventKey(marketKind, symbol, eventType, interval);
    lastReceivedAtMs.set(key, receivedAtMs);
    if (eventType !== EVENT_TYPES.DEPTH) {
      recoveryStartedAtMs.delete(key);
    }
  }

  function recordRouteConnected(marketKind, routeName) {
    connectedRoutes.add(routeKey(marketKind, routeName));
  }

  function recordRouteDisconnected(marketKind, routeName) {
    connectedRoutes.delete(routeKey(marketKind, routeName));
  }

  function isRouteConnected(marketKind, routeName) {
    return connectedRoutes.has(routeKey(marketKind, routeName));
  }

  function beginRecovery(marketKind, symbol, eventType, interval) {
    recoveryStartedAtMs.set(eventKey(marketKind, symbol, eventType, interval), now());
  }

  function endRecovery(marketKind, symbol, eventType, interval) {
    recoveryStartedAtMs.delete(eventKey(marketKind, symbol, eventType, interval));
  }

  function isRecovering(marketKind, symbol, eventType, interval) {
    return recoveryStartedAtMs.has(eventKey(marketKind, symbol, eventType, interval));
  }

  function computeContext({ marketKind, symbol, eventType, interval, routeConnected, nowMs, staleMs, recoveryStaleMs }) {
    const key = eventKey(marketKind, symbol, eventType, interval);
    const resolvedNowMs = Number.isInteger(nowMs) ? nowMs : now();

    if (!routeConnected) {
      return Object.freeze({ stale: true, recoveryState: UNAVAILABLE });
    }
    const recoveryStartedAt = recoveryStartedAtMs.get(key);
    if (recoveryStartedAt !== undefined) {
      const threshold = Number.isInteger(recoveryStaleMs)
        ? recoveryStaleMs
        : Number.isInteger(staleMs) ? staleMs : defaultStaleMs(eventType, interval);
      if (resolvedNowMs - recoveryStartedAt > threshold) {
        return Object.freeze({ stale: true, recoveryState: UNAVAILABLE });
      }
      return Object.freeze({ stale: true, recoveryState: RECOVERING });
    }

    const lastAtMs = lastReceivedAtMs.get(key);
    if (lastAtMs === undefined) {
      return Object.freeze({ stale: false, recoveryState: READY });
    }

    const threshold = Number.isInteger(staleMs) ? staleMs : defaultStaleMs(eventType, interval);
    const stale = resolvedNowMs - lastAtMs > threshold;
    return Object.freeze({ stale, recoveryState: READY });
  }

  return Object.freeze({
    recordEvent,
    recordRouteConnected,
    recordRouteDisconnected,
    isRouteConnected,
    beginRecovery,
    endRecovery,
    isRecovering,
    computeContext,
  });
}

async function performGetRequest({ controller, fetchImpl, maxResponseBytes, url }) {
  let response;
  try {
    response = await Reflect.apply(fetchImpl, undefined, [
      url.toString(),
      { method: "GET", redirect: "error", signal: controller.signal },
    ]);
  } catch (error) {
    return error?.name === "AbortError" ? failure("TIMEOUT") : failure("NETWORK_ERROR");
  }

  if (!isGenuineResponse(response)) {
    return failure("INVALID_RESPONSE");
  }

  let headers;
  let status;
  try {
    headers = plainHeadersFrom(response.headers);
    status = response.status;
  } catch {
    return failure("INVALID_RESPONSE");
  }

  if (status < 200 || status >= 300) {
    await discardResponseBody(response);
    if (status === 429 || status === 418) {
      const retryAfterMs = parseRetryAfterMs(headers);
      return failure("RATE_LIMITED", retryAfterMs === undefined ? {} : { retryAfterMs });
    }
    return failure("HTTP_ERROR");
  }

  const read = await readBoundedBody(response, maxResponseBytes);
  if (!read.ok) {
    return read;
  }

  const parsed = decodeJson(read.value.bytes);
  if (!parsed.ok) {
    return parsed;
  }

  return success({ status, headers, body: parsed.value.body });
}

This needs revision. It is a detailed infrastructure proposal, but it does not specify an indicator, and several transport assumptions could make existing indicators misleading. I reviewed both requested contract files and the relevant runtime paths.

1. **Specific trading question: missing.**  
   “Keep Binance spot data available when WebSockets fail” is an operational objective. It does not answer a retail trading question. Either submit this as a transport brief with infrastructure acceptance criteria, or supply a separate indicator brief naming its question, output, and interpretation.

2. **Incremental calculation: partially specified, with recovery gaps.**  
   Cursor paging and updating candles by open time are sensible. The brief still needs:
   
   - A bar cursor and catch-up procedure after outages longer than one minute. A moving two-row window can skip unobserved closes; a fixed window can remain behind indefinitely.
   - Classification of **each row** by open time and confirmed exchange time, rather than assuming row 0 is closed and row 1 is forming. Local receipt time can close a bar early if the machine clock is ahead.
   - Explicit replacement semantics: revisions replace the same bar, finalization occurs once, and delayed responses cannot overwrite newer revisions.
   - Per-pair serialization, cancellation, and rejection of responses from an obsolete subscription.
   
   No deliberate future-data dependency is apparent, but “free of future data” alone does not establish correct forming-bar behavior.

3. **Inputs exist, but their claimed equivalence is inaccurate.**  
   Three blockers matter most:
   
   - **Aggregate trades are not individual prints.** Binance combines fills from the same taker order at the same price and time. Large-print thresholds, print counts, and size distributions can therefore change. The proposed parity test cannot require identical quantity “per print.” Compare summed sided volume over aligned, complete ranges, and explicitly gate or label print-sensitive indicators. [Binance market-data specification](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/market)
   - **Snapshot differences do not preserve L2 coverage.** Restricting changes to overlapping windows omits newly exposed levels and retains old levels that leave coverage. In the current `memory-engine.js`, `coverageOf()` runs on seed/resync, not every live delta; `live-binding.js` supplies no coverage transition here. The claimed continuously accurate coverage does not follow from this design. Either implement explicit coverage reconciliation or keep this source unavailable to continuous-depth analytics. Snapshot observations also cannot establish unseen replenishment or cancellation activity.
   - **Failures cannot currently produce the promised recovery behavior.** The HTTP client maps both 429 and 418 to `RATE_LIMITED`, discarding status and response headers. Preserve those fields. Also specify how a failed depth poll signals a gap immediately: `binanceDepthFrame()` needs an invocation, and “failed polls emit nothing” does not itself notify the L2 engine.
   
   Telemetry alone is insufficient for trade-ID gaps. Mark affected data incomplete and define when completeness resumes. Under the SDK contract, incomplete prints must not masquerade as `LIVE_COMPLETE`; missing history must remain unavailable.

4. **Default view: insufficiently honest.**  
   `REST_POLL` identifies implementation, but does not explain the trader-facing limitation. Specify a concise visible message such as “Polled spot data · aggregate trades · snapshot book,” with unavailable analytics clearly identified. Backend environment settings are not primary indicator controls; there is no indicator view or control set to evaluate yet.

5. **Success criteria: testable in part; baseline needs correction.**  
   Connection, rendering, regression tests, and documentation checks are useful. Add deterministic cases for multi-minute outages, clock skew, moving book boundaries, genuine multi-fill aggregates, pagination backlog, and unsubscribe during an in-flight request.
   
   Correct the budget model: Binance currently documents klines at **weight 2**, including the small polling request. One pair therefore costs **3360/minute** before probes, backfill, and extra trade pages. [Binance endpoint weights](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/market)
   
   Reserve projected weight **before dispatch**, including concurrent requests and backfill. Stopping after a header reaches the budget can overshoot it. Define behavior when mandatory trades alone exceed the budget; “never stretch trades” cannot hold for every permitted configuration. A maximum setting of 6000 also contradicts the claimed minimum 2000 margin.
   
   Use connected WS as the baseline for semantic comparisons and blocked WS for availability improvement. Compare completed candles and aligned volume totals; document expected differences in print counts, latency, and depth observations. A ten-minute smoke test cannot establish semantic parity.

6. **Simplest alternative.**  
   Ship the endpoint override first for environments that support WebSockets. For this container, start with REST candles and visibly identified aggregate trades, leaving continuous-depth-dependent analytics unavailable. That delivers basic chart and sided-flow visibility without presenting sampled snapshots as a trustworthy event stream.
