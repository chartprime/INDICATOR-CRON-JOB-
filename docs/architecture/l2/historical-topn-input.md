# Historical Databento top-10 input

`historical-topn-frames.js` translates one canonical `depth` row at a time into the existing L2 engine's `book` and `gap` frames. It accepts `SNAPSHOT` / `TOP_N` rows at the declared depth limit. Each row's bids and asks are a complete **observed top-N state**, not a full-depth book or a provider reset. A canonical `reset=true` accompanies every such row; it does not reset the engine on its own.

The caller reads one instrument under a pinned catalog generation in the archive's order `(event_ns, source_rank, stable_position, ordinal)`. It must pass the returned frames to `engine.apply(frame)` in order. When `restartEngine` is true, it must construct a fresh engine **before** applying those frames and close the old derived segment with the returned reason. The first READY frame seeds the fresh engine; the preceding gap frame records why the old segment ended. A consumer that cannot restart must refuse the transition rather than apply it to the old engine. Ordinary top-N edge changes carry explicit coverage on the book frame and keep the engine segment open. Historical top-N processing requires one price per engine key (`clusterTicks=1`).

| Transition | Treatment |
|---|---|
| Same price remains visible and size changes | Emit its new absolute size as a delta. |
| Previously visible price is absent but falls **inside** the new observed range | Emit zero: the snapshot proves absence there. |
| A side contains fewer than N levels | Its outside is observed empty; a later outer entry or removal is a real change, not a depth-edge ambiguity. |
| A price exits beyond the new tenth-level edge | End observation for that price with `coverage_exit`. Drop its size history; do not infer fill, pull or cancellation. Other observed lifecycles remain open. |
| A price enters from outside the previous observed range | Seed that price as pre-existing with unknown age. Do not claim it just appeared. Other observed lifecycles remain open. |
| Canonical `UNKNOWN` file boundary or changed `book_epoch` | `SOURCE_BOUNDARY_UNKNOWN`; start a new engine segment. A channel-scoped sequence jump alone is not a gap. |
| `GAP_SUSPECTED` | Close the segment and suspend READY frames. Resume only at a provider `RESET` row. |
| Date changes without a stronger boundary | `SESSION_BOUNDARY`; start a new engine segment. |
| One-sided or empty book | `INCOMPLETE_BOOK`; close trust and wait for a two-sided state. The real AAPL August 5 opening row contains only an ask. |
| Locked or crossed two-sided source book | `CROSSED_BOOK`; close trust without applying the invalid levels. The next valid two-sided snapshot seeds a fresh segment. This is a source quality interval, not a fill, pull or claim that the market is closed. |
| First two-sided book after an incomplete state | `REESTABLISHED_BOOK`; seed a fresh engine segment even when the observed delta looks ordinary. |
| Invalid depth, malformed row or non-increasing archive key | Refuse; never manufacture liquidity. |

Timestamp conversion floors exact archive nanoseconds to the millisecond required by the current engine. Export all four archive ordering fields as decimal strings; unsafe JS numeric integers are refused before source state changes. The original nanosecond key must remain in the governed ordered-event source and the derived row lineage. Equal-millisecond rows retain archive order. The input frame path uses JS numbers inside the existing engine, so exact decimal source values must remain in the archive; do not describe engine-derived floating-point fields as bit-exact decimal amounts. Price geometry and output precision must be measured and fixed before publishing a core version.

The historical runner prunes after READY book frames at a declared event-time cadence (`pruneEveryMs`, default 1,000 ms). Each new segment restarts that cadence. No wall-clock timer drives an archived replay. This bounds rolling size/flow memory and settles pending lifecycle endings reproducibly; the cadence belongs in the derivation version. The producer must also drain engine events and trade prints into its output before retention limits discard them.

CME trade batching remains a separate qualification gate. An exact timestamp/sequence join key can contain several prints and several depth records; it is not a certified atomic event boundary. Databento's [CME normalization](https://databento.com/docs/knowledge-base/datasets) distinguishes MBO event completion from already-constructed MBP schemas; do not impose MBO `F_LAST` batching on MBP-10 without source proof. The current engine settles a pending trade window on each applied delta, including an empty delta, so blindly treating every echoed trade snapshot as a new book mutation can change hidden/visible attribution. The equity flow pilot deliberately refuses CME; passing a book-only oracle does not remove this restriction.

`push(row, { observationOnly: true })` observes a verified book echo without closing a diff window. Within a trusted segment it requires every price and size to remain unchanged, otherwise it refuses before advancing source order. It emits a READY book with `delta=null` and no coverage mutation. Initial seeds and trust boundaries retain their normal treatment. This option is for a producer that has proved the source observation is not a book update; a native MBP-10 Trade action is the current candidate. Never infer the option from an unchanged ladder or from `F_LAST` alone: an actual unchanged book update still emits an empty delta and settles pending hidden volume. The common live engine and ordinary top-N path are unchanged.

`inspect_historical_trade_join.py` reports flag-confirmed candidate counts and bounded exact-key witnesses without choosing among them. `inspect_historical_native_dbn.py` verifies raw DBN bytes against the hash retained in authenticated canonical lineage, reconciles its in-day count, and reports native actions, trade book changes and bounded source-order witnesses. The raw-copy opt-in admits only `GLBX.MDP3/mbp-10` DBN under ignored pilot data, capped at 1 GiB; curated part admission remains 64 MiB. A native diagnostic is not accepted flow or lifecycle output.

`verify_historical_cme_flow.py` uses the native MBP-10 Trade actions and row positions. It requires unchanged native trade books, exact native/L1 trade multiset agreement, complete canonical native row order, and each trade's ten-level book/key/flags agreement with its canonical depth row before launching the engine. Repeated identical prints retain native order; cross-schema occurrence matching reconciles quantities rather than recovering indistinguishable record IDs. The worker explicitly observes each verified Trade echo with no delta, then applies its known-side trade. Other snapshots keep ordinary delta semantics. Unknown and outside-trust trades remain separate. Independent L1 quantities supply rolling flow and segment exclusion checks. The native trade spool is capped at two million rows / 1 GiB, with 4 GB bounded DuckDB spill; sufficient free disk is required first. Only a completed final report counts as accepted flow, and lifecycle qualification remains separate.

The [compact output contract](historical-core-contract.md) defines the next implementation target, including coverage, append-only inference updates and knowledge-time reads. It is not a published schema or proof of exact Replay restoration.

The local complete-partition qualification uses an authenticated manifest inspection, then byte/hash-verifies every admitted part under ignored `apps/runtime/data/historical-l2-pilot`. Default admission is 256 MiB compressed per source family. Larger local sessions require explicit `--max-source-bytes`, capped at 2 GiB per family; an individual part remains capped at 64 MiB. Fetching checks free disk plus a 256 MiB reserve and uses at most four source reads. Each qualification worker uses one DuckDB thread, 256 MB decode memory and a unique spill directory capped at 4 GB. This local opt-in does not change public archive admission. `verify_historical_topn_partition.py` verifies the decoded instrument identity and disjoint exact archive-key ranges, sorts each part and retains the engine across the ordered parts. Overlapping parts are refused until a bounded merge exists. It streams rows to the real JavaScript engine and reconciles the exported/replayed count to the catalog. `--output` writes the final report directly to a separate JSON file next to the pilot plan. Its metrics describe local qualification; host derivation needs separate measurements.

The engine emits `coverage_exit` for a price leaving the observed edge and clears its short size history. The wall service consumes that event in source order, retires any wall spanning the row as `wall_unobserved`, and does not produce a filled/hit/pulled verdict for it. This protects a historical wall sampler even when the price stays outside the top ten beyond the normal unknown-level hold period. A later re-entry can form a new wall; its true creation time remains unknown and must be labelled as such in the versioned historical core.

Depth and trades currently have separate Databento serving authorities (`mbp-10` and `mbp-1`). Their merge order and trade attribution at equal timestamps are **not qualified** by this adapter. `inspect_historical_trade_join.py --quote-plan ...` adds an independent trade-time BBO comparison: the quote must share the trade authority's instrument, day and version; trade/quote lineage, dataset, publisher, sequence, event/receive nanoseconds, source action and flags must agree. The probe reports all matching depth candidates and which first event record has the same prices, sizes and flags. It verifies local part hashes and decoded row counts and uses a unique spill directory. This is ordering evidence, not permission to guess a missing action, choose a side for an unknown trade, or infer fill/pull equality. The [equity flow pilot](historical-equity-flow-pilot.md) exercises that candidate and independently reconciles directional flow. The 600-byte archive depth scan estimate is still unverified and the governed depth query refuses it; this module does not relax that guard.
