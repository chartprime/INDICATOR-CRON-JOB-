# Build brief: Relative Volume by Time of Day (final, after four Codex plan rounds)

PM brief for the cycle-1 build. Shared rules: PM/WORKER-BRIEF.md. Capability
sheet: PM/CAPABILITIES.md. UX standard: PM/cycle1/ux-standard.md. Validation
protocol: PM/cycle1/validation-protocol.md. Those live outside the repository
checkout at /home/user/Terminal-L1-L2/PM/; their requirements that matter here
are restated in this brief.

## The trading question

"Is this bar's volume unusual compared with the same minute of the day on
recent sessions, or is it just the open, the close or the London/New York
overlap being its normal self?"

## Target user and decision

Intraday traders on ES, NQ, AAPL, TSLA, BTC and ETH who confirm moves with
volume. Decision: treat participation as unusual relative to recent comparable
bars, or discount it because this minute is always loud. A rolling-average
RVOL cannot tell those apart; this tool normalises recurring intraday volume
patterns before comparing. High relative volume says nothing about direction
or follow-through, and the package says so. The baseline is short and noisy,
so the claim is "unusual relative to the last N sessions at this minute", not
"unusual" in any absolute sense.

## Identity

- Folder `apps/web/src/lib/indicators/relative-volume/`; def
  `relativeVolume.ts`; pure computation in `relativeVolumeMath.ts`; tests in
  `tests/`.
- id `relativeVolume`, label `"Relative Volume (Time of Day)"`, category
  `"technical"`, placement `{ kind: "ownPane", priceLines: [1, 2, 3] }`.
- Historical Mode policy `OHLCV_POLICY`. Works on every archived instrument
  and on equities (only `bar.volume` is read; sided volume is irrelevant).
- No `timeframeGate` (it would remove the indicator and its table). For
  `interval_ms > 3_600_000` every output is `null` and the status row says
  `Time of day needs an intraday timeframe`.

## Data

`bar.ts_open`, `bar.interval_ms`, `bar.volume`, `bar.closed`, `bar.provider`
(and `assetClass`/`marketKind` only to resolve the clock). Nothing else. No
wall clock. Identity fields choose the clock convention only; availability is
governed by the OHLCV capability policy, never by provider. A bar whose
`volume` is not a finite number >= 0 contributes no observation and yields
`null`. Missing bars (gaps in `ts_open`) contribute nothing, never a zero.

Known limitation accepted by the PM: the resampler reports the nominal
`interval_ms` even for a shortened bucket (`resampleBars.ts`), so the
indicator cannot know a bar's real duration. It therefore does no duration
normalisation. The start-minute key already compares the 15:30 equity
half-hour bar only with other 15:30 bars. The one unhandled case is an
early-close session, whose last bar is shorter than its slot's usual bars; it
enters as one observation among `sessions` and the median absorbs it. State
this in the doc page.

The `ta.*` factories are top-level imports created in `createState`
(`ctx.ta` is intentionally empty); this indicator does not use them, because
its rolling window must replace an arbitrary earlier input on a correction,
which a library stream cannot do.

## Calculation (incremental, one bar at a time)

1. **Clock, one rule.** Setting `clock`: `auto` resolves to `newYork` for
   provider DXFEED or DATABENTO and to `utc` for BINANCE; `newYork` and `utc`
   force it. New York minute of day is computed the way `killzones` does it
   (reuse its `nyParts` helper or `apps/web/src/lib/chart/marketCalendar.ts`;
   no new time-zone code). There is exactly one slot family in this version.
2. **Slot key.** The bar's start minute of day in the resolved clock
   (0..1439). No division by bar length: an hourly equity bar starting 09:30
   keys 570 and the 15:30 half-hour bar keys 930; neither collides. At most
   1,440 keys.
3. **Observation.** The bar's `volume`.
4. **Baseline.** Per slot key, a ring of the last `sessions` committed
   observations `{ts_open, volume}` (default 10, range 2..60) and their
   median (even count: mean of the two middle values). Median, not mean, so one
   news day does not inflate tomorrow's baseline. The ring capacity is the only
   bound. Live state may therefore hold observations from bars the chart has
   already discarded; that is accepted and documented, and live-versus-replay
   equivalence is required only for bars whose full `sessions` lookback lies
   within the retained series.
5. **Rolling comparison.** An own ring of the last 20 committed
   `{ts_open, volume}`; `rollingMean` is their mean. Both baselines exclude the
   current bar.
6. **Read before write.** For the bar being evaluated, `slotMedian`,
   `priorCount` and `rollingMean` are read first and stored on the bar record
   as `baselineAtOpen`. Every later recomputation of that bar (replace, closed
   correction) divides by those stored values. A bar never sees its own volume
   in its denominator.
7. **Commit rule (one observation per `ts_open`, correctable).** The bar
   record is `{ts_open, volume, baselineAtOpen, committed}`. The observation is
   inserted into the slot ring and the rolling ring at the first of: (a) the
   first dispatch of that `ts_open` with `bar.closed === true`; (b) the
   arrival of a bar with a greater `ts_open` while the record is uncommitted (a
   close that never arrived), inserting the last known volume. All derived
   state is keyed by `ts_open`, so a later closed dispatch of the same
   `ts_open` with a different volume UPDATES the observation in both rings in
   place and recomputes that bar's own ratio from `baselineAtOpen`; it never
   inserts twice. A valid-to-invalid correction REMOVES the observation from
   both rings and yields `null`; invalid-to-valid inserts it. A dispatch older
   than the current record is ignored. The replay tail may be a forming bar
   (the runtime keeps supplied `closed` flags); it stays pending.
8. **Confirmation.** Outputs and the marker are provisional while
   `bar.closed === false` (lighter styling, status row `Forming`) and
   confirmed on the first closed dispatch. The marker is always for the bar of
   the current call. A bar committed by rule (b) never received a close, so its
   drawing stays provisional; that is intentional and documented, and such
   bars are excluded from the live-versus-replay marker comparison (their
   numeric outputs are still compared).
9. **Output.** `rvol = volume / slotMedian`, `null` while `priorCount <
   minSessions` (default 3) or the median is 0 or not finite. `rolling =
   volume / rollingMean`, `null` until 20 committed bars. `minSessions` is
   clamped to `<= sessions` at read time. The forming bar is divided by the
   full-bar expectation, so it grows toward its final value during the bar.
10. **Marker (the one alert condition).** `hot`: `rvol >= hotThreshold`
    (default 2) draws a small circle on the bar; `rvol >= 3` the same circle,
    larger. The marker is a pure function of the bar's current `rvol`, so a
    correction crossing the threshold in either direction adds or removes it
    on the next dispatch, and a replace redraws rather than duplicates.
11. **Status precedence, first match wins.** Unsupported timeframe; invalid
    current volume (`No usable volume`); insufficient prior samples
    (`Learning this time of day: 1 of 3 sessions`); unusable baseline
    (`No usable volume baseline`, median 0); forming (`Forming: versus
    full-bar expectation`); ready (blank).
12. **No future data.** Every value at bar t uses only bars with
    `ts_open <= t.ts_open`. Truncating the series at any index must not
    change earlier numeric outputs or earlier confirmed markers.
13. **Fail closed.** Any non-finite intermediate yields `null`.

## Default view (what a trader sees in three seconds)

(`#26a69a`, alpha) above 1, grey below 1. Line color per bar: hot (>=

the status row from rule 11. Any unavailable value shows `—`. Before warm-up
the pane is empty, never zero.

## Baseline comparison: what must be shown

Two comparison methods, both at the same threshold (2.0), on the same
eligible bars (both ready), both using volumes:
- Rolling: `volume / mean of previous 20 committed volumes`.
- Same-slot mean: `volume / mean of the slot ring` (same observations as the
  median), to separate the benefit of clock normalisation from the benefit of
  the median.

Equity fixture (deterministic, in the validation harness): 15 sessions of
390 one-minute bars starting Monday 2026-03-02 09:30 New York (this week
contains the US spring DST change on Sunday 2026-03-08, so sessions 1..5 and
6..15 have different UTC offsets while their New York start-minute keys are
identical; that is the clock test). Expected volume for minute m (0..389)
with V = 1,000: `E(m) = V * (1 + 3 * max(0, 1 - m/60)^2)` for m < 60, `V`
for 60 <= m <= 330, `V * (1 + (m - 330) / 59)` for m > 330. Noise:
`volume = round(E(m) * exp(0.15 * z))`, z standard normal from Box-Muller
(two uniforms per pair, both outputs used in order) over mulberry32 seeded
20261026. Generation order: for each session in order, for each minute in
order, one z. Then anomalies: draw (session in 4..15, minute in 90..330) pairs
one at a time with the same generator, rejecting duplicates, until 12 are
held; each replaces its bar with `round(2.5 * E(m))`. Evaluation bars:
sessions 4..15 where all methods are ready. Predictable slots: minutes 0..9
and 380..389. A false positive is a detection on an eligible non-anomaly bar.

Acceptance (descriptive, not predictive):
- Time-of-day recall on the 12 anomalies >= 11/12, and >= rolling recall
  minus one anomaly.
- Time-of-day predictable-slot false-positive rate <= 10 percent of those
  bars, and <= half of rolling's predictable-slot rate.
- Overall false-positive rates and the same-slot-mean method's numbers are
  reported beside these in the doc page, whatever they are. If the fixture
  disproves the hypothesis, the brief returns to the PM.

Control experiment (reported, not a gate): the same fixture with flat
seasonality (`E(m) = V`) and 12 anomalies drawn from all minutes, so the doc
page states how the methods compare when the clock explains nothing.

Crypto fixture (performance, retention): 12,000 one-minute bars starting
2026-03-02 00:00 UTC, expected volume `V * (1 + 0.5 * cos(2 * pi * (m -
840) / 1440))`, same noise model and generation order, seed 20261027. Timing
over bars 1..10,080; rollover over all 12,000 (the per-bar record count stays
at or under 10,080 and every ring at or under capacity); a REBUILT replay from
bars 1,921..12,000 must reproduce live outputs for every bar whose full
`sessions` lookback lies within those bars. Readiness is asserted from actual
prior observations per key, not from a calendar day number.

Further fixtures with expected outcomes:
- Gap: a session missing minutes 120..179 contributes no observations for
  those keys; the bar after the gap has an unchanged baseline.
- Early close at 13:00: the session's last bar enters its key as one
  observation; the next session's bar at that key still divides by the median
  of `sessions` observations, which one short bar does not move.
- Short-bar key check through the real resampler: feed one session of 1m
  fixture bars through `resampleBars` to the hourly timeframe and confirm the
  final bar keys 930 (15:30) and that the indicator treats it as its own slot.
- Changed-volume closed replacement: close at 100, then close again at 150;
  both ring observations become 150, that bar's ratio uses its stored
  denominator, its hot marker appears or disappears accordingly, and every
  later bar matches a replay that only saw 150. Also valid to invalid
  (observation removed, output null) and invalid to valid (inserted).
- Duplicate identical closed dispatch: no change in any output.
- Replay with a forming tail bar: the tail stays pending and provisional.

## Amendments from plan round 5 (accepted by the PM; the brief is APPROVED by PM authority after five rounds)

1. **Corrections are tail-only.** In-place update, removal or insertion of an
   observation applies only to the current tail record. A correction to any
   older bar reaches the indicator as a `REBUILT` replay (the runtime's own
   behaviour), which recreates state from scratch. Test: correct a bar after
   several successors by replaying, and compare every successor against a fresh
   replay.
2. **Eviction rollback.** When the tail's observation is inserted into a full
   ring, the evicted observation is kept as `evictedByTail` on that ring until
   the tail is superseded by a newer bar. A valid-to-invalid correction of the
   tail removes its observation and restores `evictedByTail`; invalid-to-valid
   re-inserts and re-evicts. Test valid, invalid, valid with both rings full
   and compare with a replay that saw only the final state.
3. **Lookback counts matching bars, not sessions.** A missing slot stretches
   the lookback across more calendar sessions, and the autumn New York DST
   repeat can supply two observations for one local minute on crypto under the
   `newYork` clock. Accept "last N matching bars" and label accordingly:
   control label "Lookback (matching bars)", table "7 prior"; the settings key
   stays `sessions` for brevity but the doc page explains it.
4. **Median wording.** The median limits a single short or odd bar's influence;
   it does not make it zero. Test the exact median on a fixture containing one
   shortened bar instead of asserting no change.
5. **Settings that change colours or markers replay.** `recolor` receives only
   the old colour and settings, so it cannot reclassify history under a new
   threshold, and markers and fills need refreshing too. Therefore
   `hotThreshold`, `showMarkers` and `showRolling` are `affects: "recompute"`
   (a replay at this indicator's cost is well under a second for 10,080 bars);
   only the colour pickers are `cosmetic` with `recolor`.
6. **Marker size rule.** Draw a marker only when hot; enlarge a drawn marker
   when `rvol >= 3`. With `hotThreshold > 3` every drawn marker is large.
7. **Crypto equivalence test at a feasible lookback.** Twelve thousand minutes
   hold about eight days, so no slot has ten prior observations in a seven-day
   replay. Run the REBUILT equivalence check with `sessions = 3`, assert a
   non-zero count of compared bars, and exercise full rings at the default
   capacity on the 15-session equity fixture (14 prior per slot).
8. **Report counts, not only rates**, for every comparison: eligible bars,

+import type { BarFrame } from "../../../types/frames";
+import { nyLocalMinuteOfDay } from "../killzones/killzones";

+/**
+ * Relative Volume by Time of Day: the pure, incremental machinery.
+ *
+ * One observation per committed bar is filed under the bar's start minute of
+ * day (the "slot key") in a ring of the last `sessions` observations, and in a
+ * second ring of the last 20 committed bars. A bar's ratio divides its volume
+ * by the slot ring's median read *before* the bar's own observation entered
+ * the ring (`baselineAtOpen`), so a bar never sees itself in its denominator
+ * and every later revision of that bar divides by the same number.
+ *
+ * Corrections are tail-only: a closed dispatch of the newest bar with a
+ * different volume updates the observation in place, a valid-to-invalid
+ * correction removes it (restoring whatever its insertion evicted), and
+ * invalid-to-valid re-inserts it. A correction to any older bar reaches the
+ * indicator as a full replay, which recreates this state from scratch.
+ *
+ * Exported so that a later indicator (Squeeze Breakout Context) can import the
+ * slot-median machinery as its volume confirmation.
+ */
+
+export const MINUTE_MS = 60_000;
+export const HOUR_MS = 3_600_000;
+export const DAY_MS = 86_400_000;
+export const MINUTES_PER_DAY = 1_440;
+/** Time of day needs an intraday bar: anything longer than one hour yields null. */
+export const RVOL_MAX_INTERVAL_MS = HOUR_MS;
+export const RVOL_ROLLING_LENGTH = 20;
+export const RVOL_DEFAULT_SESSIONS = 10;
+export const RVOL_MIN_SESSIONS_SETTING = 2;
+export const RVOL_MAX_SESSIONS_SETTING = 60;
+export const RVOL_DEFAULT_MIN_SESSIONS = 3;

+  sessions: number;

+  minSessions: number;
+  clock: RvolClock;

+/** `auto` is New York for the dxFeed and Databento providers and UTC for Binance. */
+export function resolveRvolClock(clock: RvolClock, provider: BarFrame["provider"]): ResolvedRvolClock {

+ * One-entry cache of the New York minute at the start of a UTC hour. The New
+ * York offset is constant inside any UTC hour (both DST changes fall on an
+ * hour boundary), so a chronological series needs one `Intl` call per hour.

+export interface ClockCache {
+  hourStart: number;
+  minuteAtHourStart: number;

+export function createClockCache(): ClockCache {
+  return { hourStart: Number.NaN, minuteAtHourStart: 0 };

+/** The bar's start minute of day (0..1439) in the resolved clock, or null for an unusable timestamp. */
+export function slotKeyOf(tsOpen: number, clock: ResolvedRvolClock, cache?: ClockCache): number | null {
+  if (!Number.isSafeInteger(tsOpen) || tsOpen < 0) return null;
+  if (clock === "utc") return Math.floor((tsOpen % DAY_MS) / MINUTE_MS);
+  const hourStart = Math.floor(tsOpen / HOUR_MS) * HOUR_MS;
+  let minuteAtHourStart: number;
+  if (cache !== undefined && cache.hourStart === hourStart) {
+    minuteAtHourStart = cache.minuteAtHourStart;
+  } else {
+    minuteAtHourStart = nyLocalMinuteOfDay(hourStart);
+    if (cache !== undefined) {
+      cache.hourStart = hourStart;
+      cache.minuteAtHourStart = minuteAtHourStart;
+    }
+  }
+  return (minuteAtHourStart + Math.floor((tsOpen - hourStart) / MINUTE_MS)) % MINUTES_PER_DAY;

+export interface ObservationRing {

+export function createRing(capacity: number): ObservationRing {
+  const size = Number.isFinite(capacity) ? Math.max(1, Math.floor(capacity)) : 1;

+export function ringInsert(ring: ObservationRing, observation: Observation): void {
+  ring.items.push(observation);
+  if (ring.items.length > ring.capacity) ring.evictedByTail = ring.items.shift() ?? null;

+/** Changes the volume of the observation filed under `tsOpen` in place; false when none is filed. */
+export function ringUpdate(ring: ObservationRing, tsOpen: number, volume: number): boolean {
+  for (let index = ring.items.length - 1; index >= 0; index -= 1) {
+    if (ring.items[index].tsOpen === tsOpen) {
+      ring.items[index].volume = volume;
+      return true;
+    }
+  }
+  return false;
+}
+
+/** Removes the observation filed under `tsOpen` and restores what its insertion evicted. */
+export function ringRemove(ring: ObservationRing, tsOpen: number): boolean {
+  for (let index = ring.items.length - 1; index >= 0; index -= 1) {
+    if (ring.items[index].tsOpen !== tsOpen) continue;
+    ring.items.splice(index, 1);
+    if (ring.evictedByTail !== null) {
+      ring.items.unshift(ring.evictedByTail);
+      ring.evictedByTail = null;
+    }
+    return true;
+  }
+  return false;

+/** Median of the ring's volumes (mean of the two middle values for an even count); null when empty. */
+export function ringMedian(ring: ObservationRing, scratch: number[] = []): number | null {
+  const count = ring.items.length;
+  if (count === 0) return null;
+  scratch.length = count;
+  for (let index = 0; index < count; index += 1) {
+    // Insertion sort: the ring holds at most 60 values and this runs once per bar.
+    const value = ring.items[index].volume;
+    let position = index;
+    while (position > 0 && scratch[position - 1] > value) {
+      scratch[position] = scratch[position - 1];
+      position -= 1;
+    }
+    scratch[position] = value;
+  }
+  const middle = count >> 1;
+  const median = count % 2 === 1 ? scratch[middle] : (scratch[middle - 1] + scratch[middle]) / 2;
+  return Number.isFinite(median) ? median : null;
+}
+
+export function ringMean(ring: ObservationRing): number | null {
+  const count = ring.items.length;
+  if (count === 0) return null;
+  let sum = 0;
+  for (let index = 0; index < count; index += 1) sum += ring.items[index].volume;
+  const mean = sum / count;
+  return Number.isFinite(mean) ? mean : null;
+}

+export function createRelativeVolumeEngine(settings: RelativeVolumeMathSettings): RelativeVolumeEngine {
+  const capacity = Number.isFinite(settings.sessions)
+    ? Math.min(RVOL_MAX_SESSIONS_SETTING, Math.max(RVOL_MIN_SESSIONS_SETTING, Math.floor(settings.sessions)))
+    : RVOL_DEFAULT_SESSIONS;
+  const slots = new Map<number, ObservationRing>();
+  const rolling = createRing(RVOL_ROLLING_LENGTH);
+  const clockCache = createClockCache();
+  const scratch: number[] = [];
+  let tail: TailRecord | null = null;
+  let current: RvolReading | null = null;
+
+  function slotFor(key: number): ObservationRing {
+    let ring = slots.get(key);
+    if (ring === undefined) {
+      ring = createRing(capacity);
+      slots.set(key, ring);
+    }
+    return ring;
+  }
+
+  function readBaseline(key: number | null): BaselineAtOpen {
+    const slot = key === null ? undefined : slots.get(key);
+    return {
+      slotMedian: slot === undefined ? null : ringMedian(slot, scratch),
+      slotMean: slot === undefined ? null : ringMean(slot),
+      priorCount: slot === undefined ? 0 : slot.items.length,
+      rollingMean: ringMean(rolling),
+      rollingCount: rolling.items.length,
+    };
+  }
+
+  /** Rule 7: the commit event for the tail, filing its last known volume when it is usable. */
+  function commit(record: TailRecord): void {
+    record.committed = true;
+    if (!record.supported || record.key === null || record.volume === null) return;
+    const observation = { tsOpen: record.tsOpen, volume: record.volume };
+    ringInsert(slotFor(record.key), observation);
+    ringInsert(rolling, { tsOpen: record.tsOpen, volume: record.volume });
+    record.inRings = true;
+  }
+
+  /** A later dispatch of a committed tail: update in place, remove (valid to invalid) or insert (invalid to valid). */
+  function reconcile(record: TailRecord): void {
+    if (!record.supported || record.key === null) return;
+    const slot = slotFor(record.key);
+    if (record.volume !== null && record.inRings) {
+      ringUpdate(slot, record.tsOpen, record.volume);
+      ringUpdate(rolling, record.tsOpen, record.volume);
+    } else if (record.volume !== null) {
+      ringInsert(slot, { tsOpen: record.tsOpen, volume: record.volume });
+      ringInsert(rolling, { tsOpen: record.tsOpen, volume: record.volume });
+      record.inRings = true;
+    } else if (record.inRings) {
+      ringRemove(slot, record.tsOpen);
+      ringRemove(rolling, record.tsOpen);
+      record.inRings = false;
+    }
+  }
+
+  function supersede(record: TailRecord): void {
+    if (record.key !== null) {
+      const slot = slots.get(record.key);
+      if (slot !== undefined) ringSupersede(slot);
+    }
+    ringSupersede(rolling);
+  }

+  function onBar(bar: BarFrame): RvolReading {
+    const tsOpen = bar.ts_open;
+    if (tail !== null && tsOpen < tail.tsOpen) {
+      // A dispatch older than the current record: the runtime replays those, so here it is ignored.
+      return current ?? readingOf(tail, settings);
+    }
+    if (tail === null || tsOpen > tail.tsOpen) {
+      if (tail !== null) {
+        if (!tail.committed) commit(tail); // rule 7(b): a close that never arrived
+        supersede(tail);
+      }
+      const intervalOk = Number.isFinite(bar.interval_ms) && bar.interval_ms > 0 && bar.interval_ms <= RVOL_MAX_INTERVAL_MS;
+      const key = intervalOk ? slotKeyOf(tsOpen, resolveRvolClock(settings.clock, bar.provider), clockCache) : null;

+        tsOpen,
+        key,

+        volume: usableVolume(bar.volume),
+        baselineAtOpen: readBaseline(key),

+        inRings: false,
+        confirmed: false,
+      };

+ * Brief, "Baseline comparison": three methods at the same threshold on the same
+ * eligible bars. Time of day (slot median) is the indicator; rolling (mean of
+ * the previous 20 committed volumes) is the baseline a plain RVOL gives; the
+ * same-slot mean separates the benefit of the clock from the benefit of the
+ * median. Counts and rates are printed as the table the doc page quotes.
+ */

+const THRESHOLD = 2;
+const METHODS = ["timeOfDay", "sameSlotMean", "rolling"] as const;
+type Method = (typeof METHODS)[number];
+
+interface MethodResult {
+  eligible: number;
+  detections: number;
+  anomaliesHit: number;
+  falsePositives: number;
+  predictableEligible: number;
+  predictableFalsePositives: number;
+}
+
+export interface ComparisonTable {
+  anomalies: number;
+  results: Record<Method, MethodResult>;
+}
+
+function emptyResult(): MethodResult {
+  return { eligible: 0, detections: 0, anomaliesHit: 0, falsePositives: 0, predictableEligible: 0, predictableFalsePositives: 0 };
+}

+export function compareMethods(fixture: ReturnType<typeof relativeVolumeEquityFixture>): ComparisonTable {
+  const { bars, labels } = fixture;
+  const engine = createRelativeVolumeEngine({ sessions: RELATIVE_VOLUME_DEFAULT_SETTINGS.sessions, minSessions: RELATIVE_VOLUME_DEFAULT_SETTINGS.minSessions, clock: "auto" });
+  const results: Record<Method, MethodResult> = { timeOfDay: emptyResult(), sameSlotMean: emptyResult(), rolling: emptyResult() };
+  const anomalyIndices = new Set(labels.anomalyIndices);
+  const predictableSlotIndices = new Set(labels.predictableSlotIndices);
+  const evaluationIndices = new Set(labels.evaluationIndices);
+  for (let index = 0; index < bars.length; index += 1) {
+    const reading = engine.onBar(bars[index]);
+    if (!evaluationIndices.has(index)) continue;
+    const ratios: Record<Method, number | null> = { timeOfDay: reading.rvol, sameSlotMean: reading.slotMeanRatio, rolling: reading.rolling };
+    // Readiness is asserted from actual prior observations per key, never from a calendar day number.
+    if (METHODS.some((method) => ratios[method] === null)) continue;
+    const anomaly = anomalyIndices.has(index);
+    const predictable = predictableSlotIndices.has(index);
+    for (const method of METHODS) {
+      const result = results[method];
+      const detected = (ratios[method] as number) >= THRESHOLD;
+      result.eligible += 1;
+      if (predictable) result.predictableEligible += 1;
+      if (detected) result.detections += 1;
+      if (anomaly && detected) result.anomaliesHit += 1;
+      if (!anomaly && detected) {
+        result.falsePositives += 1;
+        if (predictable) result.predictableFalsePositives += 1;
+      }
+    }
+  }
+  return { anomalies: labels.anomalies.length, results };
+}

+function pct(numerator: number, denominator: number): string {
+  return denominator === 0 ? "n/a" : `${((100 * numerator) / denominator).toFixed(2)}%`;
+}

+  timeOfDay: "Time of day (slot median)",
+  sameSlotMean: "Same-slot mean",
+  rolling: "Rolling 20 mean",

+export function formatComparison(title: string, table: ComparisonTable): string {

+    "| Method | Eligible bars | Detections | Anomalies hit | Recall | False positives | FP rate | Predictable-slot bars | Predictable-slot FPs | Predictable-slot FP rate |",
+    "|---|---|---|---|---|---|---|---|---|---|",
+  ];
+  for (const method of METHODS) {
+    const r = table.results[method];
+    lines.push(
+      `| ${METHOD_LABELS[method]} | ${r.eligible} | ${r.detections} | ${r.anomaliesHit}/${table.anomalies} | ${pct(r.anomaliesHit, table.anomalies)} | ${r.falsePositives} | ${pct(r.falsePositives, r.eligible - r.anomaliesHit)} | ${r.predictableEligible} | ${r.predictableFalsePositives} | ${pct(r.predictableFalsePositives, r.predictableEligible)} |`,
+    );
+  }
+  return lines.join("\n");

+# Relative Volume (Time of Day)
+
+[Handbook](../../README.md) · [Indicator index](README.md) ·
+[Data for indicator authors](data-for-indicator-authors.md) ·
+[Setting presets](setting-presets.md)
+
+Code: `apps/web/src/lib/indicators/relative-volume/` (`relativeVolume.ts` is
+the registry definition, `relativeVolumeMath.ts` the pure machinery, `tests/`
+the evidence). Registry id `relativeVolume`, label "Relative Volume (Time of
+Day)", category technical, own pane. The code wins over this page.
+
+## The question it answers
+
+"Is this bar's volume unusual compared with the same minute of the day on
+recent sessions, or is it just the open, the close or the London/New York
+overlap being its normal self?"
+
+A rolling-average relative volume compares a bar with the twenty bars before
+it, so the first minute of a cash session always looks loud and the lunch hour
+always looks dead. This indicator compares a bar only with bars that started at
+the same minute of the day on earlier sessions. High relative volume says
+nothing about direction or follow-through; the colours are purple and blue so
+nothing on the pane reads as buy or sell. The baseline is short and noisy, so
+the claim is "unusual relative to the last N matching bars at this minute", not
+"unusual" in any absolute sense. Descriptive only.
+
+## Calculation
+
+One bar at a time, incrementally; `onBar` never rebuilds from an array.
+
+1. **Clock.** The `clock` setting: `auto` is New York for the dxFeed and
+   Databento providers and UTC for Binance; `newYork` and `utc` force it. The
+   New York minute of day comes from the killzones helper
+   (`nyLocalMinuteOfDay`), cached once per UTC hour; there is no new
+   time-zone code.
+2. **Slot key.** The bar's start minute of day in that clock (0..1439). There
+   is no division by bar length: an hourly equity bar starting 09:30 keys 570
+   and the 15:30 half-hour bar keys 930, so they never collide. At most 1,440
+   keys exist.
+3. **Observation.** The bar's `volume`. A volume that is not a finite number
+   at or above zero contributes nothing and the bar reads `null`.
+4. **Baseline.** Per slot key, a ring of the last `sessions` committed
+   observations (default 10, range 2..60) and their median (even count: mean
+   of the two middle values). Median, not mean, so one news day does not
+   inflate tomorrow's baseline. The ring capacity is the only bound.
+5. **Rolling comparison.** A ring of the last 20 committed bars; its mean is
+   the plain relative-volume baseline, shown for comparison.
+6. **Read before write.** When a bar first arrives, the slot median, the count
+   of prior observations and the rolling mean are read and stored on the bar
+   record. Every later recomputation of that bar (a forming revision, a
+   corrected close) divides by those stored values. A bar never sees its own
+   volume in its denominator.
+7. **Commit.** One observation per `ts_open`, filed into both rings at the
+   first of: the first dispatch with `closed: true`, or the arrival of a bar
+   with a greater `ts_open` while the record is still open (a close that never
+   arrived; the last known volume is filed). A later closed dispatch of the
+   same bar with a different volume updates the observation in place; a
+   valid-to-invalid correction removes it and restores whatever its insertion
+   evicted; invalid-to-valid re-inserts it. Corrections are tail-only: a
+   correction to an older bar reaches the indicator as the runtime's full
+   replay, which recreates this state from scratch.
+8. **Outputs.** `rvol = volume / slot median`, `null` while the slot has fewer
+   than `minSessions` prior observations (default 3, clamped to `sessions`)
+   or the median is zero. `rolling = volume / rolling mean`, `null` until 20
+   bars are committed. The forming bar is divided by the full-bar
+   expectation, so it grows toward its final value during the bar.
+9. **Fail closed.** Any non-finite intermediate yields `null`; nothing ever
+   emits `NaN`.
+
+Lookback counts **matching bars, not calendar sessions**: a missing slot
+stretches the lookback across more sessions, and the autumn New York DST
+repeat can supply two observations for one local minute on crypto under the
+`newYork` clock. The table therefore says "7 prior" and the control is
+"Lookback (prior bars)".
+
+## Data and the clock rule
+
+Reads `bar.ts_open`, `bar.interval_ms`, `bar.volume`, `bar.closed` and
+`bar.provider` (the provider only picks the clock). No sided volume, no ticks,
+no order book, no wall clock. Missing bars (gaps in `ts_open`) contribute
+nothing, never a zero; the rolling comparison carries across a gap because it
+counts committed bars, not minutes.
+
+Timeframes longer than one hour cannot be keyed by minute of day: every output
+is `null` and the table says `Needs 1m to 1h`. There is no `timeframeGate`, so
+the pane and the table stay on the chart to say so.
+
+The resampler reports the nominal `interval_ms` even for a shortened bucket
+(the 15:30 equity half hour, an early-close session's last bar), so the
+indicator cannot know a bar's real duration and does **no duration
+normalisation**. The start-minute key already compares the 15:30 bar only with
+other 15:30 bars. The one unhandled case is an early-close session, whose last
+bar is shorter than its slot's usual bars; it enters as one observation among
+`sessions` and the median limits its influence without removing it (on the
+test fixture one 30-minute bar among three full hours moves the median from
+60 to 59).
+
+## Default view
+
+Own pane with `autoscaleRange` 0..4 and dotted reference lines at 1, 2 and 3.
+Those lines are **fixed reference marks**: they do not move when "Unusual
+above" is changed; the exact ratio is in the table.
+
+- One line, `rvol`, width 2: purple `#8672b3` at or above 1, blue `#2563eb`
+  when at or above the "unusual" threshold, grey `#787b86` below 1.
+- One fill between the line and 1, `rgba(134,114,179,0.15)`, above 1 only.
+- A circle above the bar when the bar is unusual (section "Alert conditions").
+- The rolling comparison line (width 1, grey) is off by default; its value is
+  always in the table.
+- While a bar is forming, its line colour, marker and table value use the same
+  hues at 50 percent alpha; they settle at the close.
+- Table, top right, three rows: `RVOL 2.4× · 7 prior` coloured like the line
+  (the count is the prior observations in the denominator, excluding this
+  bar), `Rolling 1.1× · 20 bars`, and a status row. Unavailable values show
+  `—`. Before warm-up the pane is empty, never zero.
+
+Status row, first match wins: `Needs 1m to 1h`, `No usable volume`,
+`Learning · 1 of 3 prior`, `No usable baseline` (median 0), `Forming · vs full
+bar`, and blank when the bar is ready and closed. The `draw.table` handle has
+no way to drop a row once written, so the blank status row stays as an empty
+strip when ready; removing it entirely needs a `TableHandle` change in
+`apps/web/src/lib/chart/draw/table.ts`.

+`hotThreshold`, `showMarkers` and `showRolling` are `recompute`: a per-bar

+and markers need refreshing, so these replay (well under a second for 10,080
+bars). The colour pickers are `cosmetic`; the rolling line recolours in place,
+and a change to the line or unusual colour also replays, for the same reason.
+Every key is in the schema, so [presets](setting-presets.md) work without any
+extra code.
+
+## Alert conditions
+
+There is no notification channel; an alert condition is a marker plus a table
+row.
+
+**Unusual volume.** Rule: `rvol >= hotThreshold` (default 2) on the bar of the
+current call. It fires on that bar, as a circle above the bar in the unusual
+colour, size 1, enlarged to size 2 when `rvol >= 3` (with a threshold above 3
+every drawn marker is large). The marker is a pure function of the bar's
+current ratio: it appears while the bar forms (at 50 percent alpha), **confirms
+at the bar close**, and a correction crossing the threshold in either direction
+adds or removes it on the next dispatch; a forming revision redraws rather than
+duplicates. A bar whose close never arrived keeps its provisional marker. The
+table's first row carries the same ratio in the same colour.
+
+Fixture rate: on the frozen 15-session equity fixture at the default threshold,
+13 markers over the 4,680 evaluated bars (sessions 4..15), 0.28 per 100 bars
+(2.2 per 1,000), at most one per bar; the twelve labelled anomalies plus one
+noise bar. The protocol ceiling is 40 per 1,000 for a signal tool.
+
+## Warm-up
+
+A slot shows a ratio once it holds `minSessions` prior observations (three by
+default), so a fresh symbol shows `Learning · n of 3 prior` for three sessions
+at every minute. The rolling comparison needs 20 committed bars. On one-minute
+bars the chart retains 10,080 bars: about seven UTC days for crypto, about 25
+regular sessions for equities, so the default lookback of ten fits; a
+60-bar lookback on one-minute crypto never fills. Hourly bars warm up after
+three sessions as well, since the key is the start minute, not the bar count.
+
+## Replay and Historical Mode
+
+Candle-only, policy `OHLCV_POLICY`: it works on every archived instrument and
+on equities (equity candles are regular session only, so the New York keys run
+570..959). A clean replay and a live feed with forming revisions end on the
+same committed numbers and the same confirmed markers; the validation tests
+pin this on the equity and crypto fixtures (`relativeVolumeValidation.test.ts`).
+
+One documented difference: live state keeps observations from bars the chart
+has already discarded past its 10,080-bar retention, while a replay starts
+from the retained bars. Live-versus-replay equivalence therefore holds for
+every bar whose full lookback lies within the retained series; on the 12,000-bar
+crypto fixture at a lookback of 3 that is 5,760 of the 10,080 retained bars,
+and the first 1,920 retained bars differ by design. A bar committed because its
+close never arrived keeps provisional styling live, which a replay (where every
+bar is closed) does not show; its numbers still match.
+
+Truncation invariance (no future data) holds at every cut: a bar's committed
+output and confirmed marker never change when later bars are added.
+

+## Limitations
+
+- Needs `minSessions` prior observations per slot: one-minute crypto retains
+  seven UTC days, one-minute equities about 25 sessions; a fresh symbol shows
+  "learning" for three sessions.
+- Holidays and early closes are ordinary sessions; an early-close session's
+  short last bar is one observation among `sessions` (section "Data").
+- No duration normalisation (nominal `interval_ms`).
+- Equity candles are regular session only, so no pre-market or after-hours
+  slots exist.
+- Weekend behaviour on crypto is not separated: a Saturday 14:00 bar is
+  compared with weekday 14:00 bars. A weekend slot family is deferred.
+- The ratio is unit-free; volume units are the provider's (Binance base
+  asset, futures contracts, equity shares).
+- Descriptive only: high relative volume says nothing about direction or
+  follow-through, and nothing here is a prediction.
+- The status row cannot be removed once written (section "Default view").
+- No tooltip: an SDK indicator has no hover today, so everything a trader needs
+  is in the table and on the reference lines.

import type { BarFrame } from "../../../types/frames";
import { nyLocalMinuteOfDay } from "../killzones/killzones";

/**
 * Relative Volume by Time of Day: the pure, incremental machinery.
 *
 * One observation per committed bar is filed under the bar's start minute of
 * day (the "slot key") in a ring of the last `sessions` observations, and in a
 * second ring of the last 20 committed bars. A bar's ratio divides its volume
 * by the slot ring's median read *before* the bar's own observation entered
 * the ring (`baselineAtOpen`), so a bar never sees itself in its denominator
 * and every later revision of that bar divides by the same number.
 *
 * Corrections are tail-only: a closed dispatch of the newest bar with a
 * different volume updates the observation in place, a valid-to-invalid
 * correction removes it (restoring whatever its insertion evicted), and
 * invalid-to-valid re-inserts it. A correction to any older bar reaches the
 * indicator as a full replay, which recreates this state from scratch.
 *
 * Exported so that a later indicator (Squeeze Breakout Context) can import the
 * slot-median machinery as its volume confirmation.
 */

export const MINUTE_MS = 60_000;
export const HOUR_MS = 3_600_000;
export const DAY_MS = 86_400_000;
export const MINUTES_PER_DAY = 1_440;
/** Time of day needs an intraday bar: anything longer than one hour yields null. */
export const RVOL_MAX_INTERVAL_MS = HOUR_MS;
export const RVOL_ROLLING_LENGTH = 20;
export const RVOL_DEFAULT_SESSIONS = 10;
export const RVOL_MIN_SESSIONS_SETTING = 2;
export const RVOL_MAX_SESSIONS_SETTING = 60;
export const RVOL_DEFAULT_MIN_SESSIONS = 3;

export type RvolClock = "auto" | "newYork" | "utc";
export type ResolvedRvolClock = "newYork" | "utc";

export interface RelativeVolumeMathSettings {
  /** Ring capacity per slot key: the last N matching bars (2..60). */
  sessions: number;
  /** Prior observations a slot needs before a ratio is shown; clamped to `sessions` at read time. */
  minSessions: number;
  clock: RvolClock;
}

/** `auto` is New York for the dxFeed and Databento providers and UTC for Binance. */
export function resolveRvolClock(clock: RvolClock, provider: BarFrame["provider"]): ResolvedRvolClock {
  if (clock === "newYork" || clock === "utc") return clock;
  return provider === "DXFEED" || provider === "DATABENTO" ? "newYork" : "utc";
}

/**
 * One-entry cache of the New York minute at the start of a UTC hour. The New
 * York offset is constant inside any UTC hour (both DST changes fall on an
 * hour boundary), so a chronological series needs one `Intl` call per hour.
 */
export interface ClockCache {
  hourStart: number;
  minuteAtHourStart: number;
}

export function createClockCache(): ClockCache {
  return { hourStart: Number.NaN, minuteAtHourStart: 0 };
}

/** The bar's start minute of day (0..1439) in the resolved clock, or null for an unusable timestamp. */
export function slotKeyOf(tsOpen: number, clock: ResolvedRvolClock, cache?: ClockCache): number | null {
  if (!Number.isSafeInteger(tsOpen) || tsOpen < 0) return null;
  if (clock === "utc") return Math.floor((tsOpen % DAY_MS) / MINUTE_MS);
  const hourStart = Math.floor(tsOpen / HOUR_MS) * HOUR_MS;
  let minuteAtHourStart: number;
  if (cache !== undefined && cache.hourStart === hourStart) {
    minuteAtHourStart = cache.minuteAtHourStart;
  } else {
    minuteAtHourStart = nyLocalMinuteOfDay(hourStart);
    if (cache !== undefined) {
      cache.hourStart = hourStart;
      cache.minuteAtHourStart = minuteAtHourStart;
    }
  }
  return (minuteAtHourStart + Math.floor((tsOpen - hourStart) / MINUTE_MS)) % MINUTES_PER_DAY;
}

/** A finite volume at or above zero; anything else contributes no observation. */
export function usableVolume(volume: unknown): number | null {
  return typeof volume === "number" && Number.isFinite(volume) && volume >= 0 ? volume : null;
}

export interface Observation {
  tsOpen: number;
  volume: number;
}

export interface ObservationRing {
  readonly capacity: number;
  /** Oldest first; never longer than `capacity`. */
  readonly items: Observation[];
  /** What the newest insertion pushed out, kept until that tail is superseded so a correction can restore it. */
  evictedByTail: Observation | null;
}

export function createRing(capacity: number): ObservationRing {
  const size = Number.isFinite(capacity) ? Math.max(1, Math.floor(capacity)) : 1;
  return { capacity: size, items: [], evictedByTail: null };
}

export function ringInsert(ring: ObservationRing, observation: Observation): void {
  ring.items.push(observation);
  if (ring.items.length > ring.capacity) ring.evictedByTail = ring.items.shift() ?? null;
}

/** Changes the volume of the observation filed under `tsOpen` in place; false when none is filed. */
export function ringUpdate(ring: ObservationRing, tsOpen: number, volume: number): boolean {
  for (let index = ring.items.length - 1; index >= 0; index -= 1) {
    if (ring.items[index].tsOpen === tsOpen) {
      ring.items[index].volume = volume;
      return true;
    }
  }
  return false;
}

/** Removes the observation filed under `tsOpen` and restores what its insertion evicted. */
export function ringRemove(ring: ObservationRing, tsOpen: number): boolean {
  for (let index = ring.items.length - 1; index >= 0; index -= 1) {
    if (ring.items[index].tsOpen !== tsOpen) continue;
    ring.items.splice(index, 1);
    if (ring.evictedByTail !== null) {
      ring.items.unshift(ring.evictedByTail);
      ring.evictedByTail = null;
    }
    return true;
  }
  return false;
}

/** The tail that inserted into this ring has been superseded by a newer bar: its eviction is final. */
export function ringSupersede(ring: ObservationRing): void {
  ring.evictedByTail = null;
}

/** Median of the ring's volumes (mean of the two middle values for an even count); null when empty. */
export function ringMedian(ring: ObservationRing, scratch: number[] = []): number | null {
  const count = ring.items.length;
  if (count === 0) return null;
  scratch.length = count;
  for (let index = 0; index < count; index += 1) {
    // Insertion sort: the ring holds at most 60 values and this runs once per bar.
    const value = ring.items[index].volume;
    let position = index;
    while (position > 0 && scratch[position - 1] > value) {
      scratch[position] = scratch[position - 1];
      position -= 1;
    }
    scratch[position] = value;
  }
  const middle = count >> 1;
  const median = count % 2 === 1 ? scratch[middle] : (scratch[middle - 1] + scratch[middle]) / 2;
  return Number.isFinite(median) ? median : null;
}

export function ringMean(ring: ObservationRing): number | null {
  const count = ring.items.length;
  if (count === 0) return null;
  let sum = 0;
  for (let index = 0; index < count; index += 1) sum += ring.items[index].volume;
  const mean = sum / count;
  return Number.isFinite(mean) ? mean : null;
}

/** What the baselines were before this bar's observation existed: read once, stored on the bar record. */
export interface BaselineAtOpen {
  slotMedian: number | null;
  slotMean: number | null;
  priorCount: number;
  rollingMean: number | null;
  rollingCount: number;
}

export interface TailRecord {
  tsOpen: number;
  /** Start minute of day in the resolved clock; null when the bar cannot be keyed. */
  key: number | null;
  /** False for a timeframe longer than one hour or an unkeyable bar: nothing is filed, every output is null. */
  supported: boolean;
  /** Last known volume, null when the latest dispatch carried no usable volume. */
  volume: number | null;
  baselineAtOpen: BaselineAtOpen;
  /** The commit event (first closed dispatch, or a newer bar arriving) has happened. */
  committed: boolean;
  /** An observation for this bar currently sits in both rings. */
  inRings: boolean;
  /** A closed dispatch has been seen: outputs are confirmed, not provisional. */
  confirmed: boolean;
}

export type RvolStatus = "unsupported" | "noVolume" | "learning" | "noBaseline" | "forming" | "ready";

export interface RvolReading {
  tsOpen: number;
  key: number | null;
  volume: number | null;
  /** volume / median of the slot ring as it stood when this bar opened. */
  rvol: number | null;
  /** volume / mean of the last 20 committed bars as they stood when this bar opened. */
  rolling: number | null;
  /** volume / mean of the same slot observations the median uses (the baseline comparison's second method). */
  slotMeanRatio: number | null;
  priorCount: number;
  rollingCount: number;
  /** `minSessions` clamped to `sessions`: what `priorCount` must reach. */
  requiredPrior: number;
  confirmed: boolean;
  status: RvolStatus;
}

export interface RelativeVolumeEngine {
  readonly settings: RelativeVolumeMathSettings;
  /** Feeds one dispatch of a bar and returns the reading for the bar of this call (the tail). */
  onBar(bar: BarFrame): RvolReading;
  readonly current: RvolReading | null;
  readonly tail: TailRecord | null;
  readonly rollingRing: ObservationRing;
  slotRing(key: number): ObservationRing | undefined;
  readonly slotCount: number;
}

export function requiredPriorOf(settings: RelativeVolumeMathSettings): number {
  const sessions = Number.isFinite(settings.sessions) ? Math.floor(settings.sessions) : RVOL_DEFAULT_SESSIONS;
  const minimum = Number.isFinite(settings.minSessions) ? Math.floor(settings.minSessions) : RVOL_DEFAULT_MIN_SESSIONS;
  return Math.max(1, Math.min(minimum, sessions));
}

function ratioOf(volume: number, denominator: number | null): number | null {
  if (denominator === null || !(denominator > 0)) return null;
  const ratio = volume / denominator;
  return Number.isFinite(ratio) ? ratio : null;
}

/** The reading for a tail record: rule 9 (outputs) and rule 11 (status precedence, first match wins). */
export function readingOf(tail: TailRecord, settings: RelativeVolumeMathSettings): RvolReading {
  const requiredPrior = requiredPriorOf(settings);
  const base = tail.baselineAtOpen;
  const reading: RvolReading = {
    tsOpen: tail.tsOpen,
    key: tail.key,
    volume: tail.volume,
    rvol: null,
    rolling: null,
    slotMeanRatio: null,
    priorCount: base.priorCount,
    rollingCount: base.rollingCount,
    requiredPrior,
    confirmed: tail.confirmed,
    status: "ready",
  };
  if (!tail.supported) {
    reading.status = "unsupported";
    return reading;
  }
  if (tail.volume === null) {
    reading.status = "noVolume";
    return reading;
  }
  reading.rolling = base.rollingCount >= RVOL_ROLLING_LENGTH ? ratioOf(tail.volume, base.rollingMean) : null;
  if (base.priorCount < requiredPrior) {
    reading.status = "learning";
    return reading;
  }
  reading.slotMeanRatio = ratioOf(tail.volume, base.slotMean);
  reading.rvol = ratioOf(tail.volume, base.slotMedian);
  if (reading.rvol === null) {
    reading.status = "noBaseline";
    return reading;
  }
  reading.status = tail.confirmed ? "ready" : "forming";
  return reading;
}

export function createRelativeVolumeEngine(settings: RelativeVolumeMathSettings): RelativeVolumeEngine {
  const capacity = Number.isFinite(settings.sessions)
    ? Math.min(RVOL_MAX_SESSIONS_SETTING, Math.max(RVOL_MIN_SESSIONS_SETTING, Math.floor(settings.sessions)))
    : RVOL_DEFAULT_SESSIONS;
  const slots = new Map<number, ObservationRing>();
  const rolling = createRing(RVOL_ROLLING_LENGTH);
  const clockCache = createClockCache();
  const scratch: number[] = [];
  let tail: TailRecord | null = null;
  let current: RvolReading | null = null;

  function slotFor(key: number): ObservationRing {
    let ring = slots.get(key);
    if (ring === undefined) {
      ring = createRing(capacity);
      slots.set(key, ring);
    }
    return ring;
  }

  function readBaseline(key: number | null): BaselineAtOpen {
    const slot = key === null ? undefined : slots.get(key);
    return {
      slotMedian: slot === undefined ? null : ringMedian(slot, scratch),
      slotMean: slot === undefined ? null : ringMean(slot),
      priorCount: slot === undefined ? 0 : slot.items.length,
      rollingMean: ringMean(rolling),
      rollingCount: rolling.items.length,
    };
  }

  /** Rule 7: the commit event for the tail, filing its last known volume when it is usable. */
  function commit(record: TailRecord): void {
    record.committed = true;
    if (!record.supported || record.key === null || record.volume === null) return;
    const observation = { tsOpen: record.tsOpen, volume: record.volume };
    ringInsert(slotFor(record.key), observation);
    ringInsert(rolling, { tsOpen: record.tsOpen, volume: record.volume });
    record.inRings = true;
  }

  /** A later dispatch of a committed tail: update in place, remove (valid to invalid) or insert (invalid to valid). */
  function reconcile(record: TailRecord): void {
    if (!record.supported || record.key === null) return;
    const slot = slotFor(record.key);
    if (record.volume !== null && record.inRings) {
      ringUpdate(slot, record.tsOpen, record.volume);
      ringUpdate(rolling, record.tsOpen, record.volume);
    } else if (record.volume !== null) {
      ringInsert(slot, { tsOpen: record.tsOpen, volume: record.volume });
      ringInsert(rolling, { tsOpen: record.tsOpen, volume: record.volume });
      record.inRings = true;
    } else if (record.inRings) {
      ringRemove(slot, record.tsOpen);
      ringRemove(rolling, record.tsOpen);
      record.inRings = false;
    }
  }

  function supersede(record: TailRecord): void {
    if (record.key !== null) {
      const slot = slots.get(record.key);
      if (slot !== undefined) ringSupersede(slot);
    }
    ringSupersede(rolling);
  }

  function onBar(bar: BarFrame): RvolReading {
    const tsOpen = bar.ts_open;
    if (tail !== null && tsOpen < tail.tsOpen) {
      // A dispatch older than the current record: the runtime replays those, so here it is ignored.
      return current ?? readingOf(tail, settings);
    }
    if (tail === null || tsOpen > tail.tsOpen) {
      if (tail !== null) {
        if (!tail.committed) commit(tail); // rule 7(b): a close that never arrived
        supersede(tail);
      }
      const intervalOk = Number.isFinite(bar.interval_ms) && bar.interval_ms > 0 && bar.interval_ms <= RVOL_MAX_INTERVAL_MS;
      const key = intervalOk ? slotKeyOf(tsOpen, resolveRvolClock(settings.clock, bar.provider), clockCache) : null;
      tail = {
        tsOpen,
        key,
        supported: intervalOk && key !== null,
        volume: usableVolume(bar.volume),
        baselineAtOpen: readBaseline(key),
        committed: false,
        inRings: false,
        confirmed: false,
      };
    } else {
      tail.volume = usableVolume(bar.volume);
    }
    if (bar.closed === true) tail.confirmed = true;
    if (!tail.committed) {
      if (bar.closed === true) commit(tail); // rule 7(a)
    } else {
      reconcile(tail);
    }
    current = readingOf(tail, settings);
    return current;
  }

  return {
    settings,
    onBar,
    get current() {
      return current;
    },
    get tail() {
      return tail;
    },
    rollingRing: rolling,
    slotRing: (key) => slots.get(key),
    get slotCount() {
      return slots.size;
    },
  };
}

/**
 * Brief, "Baseline comparison": three methods at the same threshold on the same
 * eligible bars. Time of day (slot median) is the indicator; rolling (mean of
 * the previous 20 committed volumes) is the baseline a plain RVOL gives; the
 * same-slot mean separates the benefit of the clock from the benefit of the
 * median. Counts and rates are printed as the table the doc page quotes.
 */

const THRESHOLD = 2;
const METHODS = ["timeOfDay", "sameSlotMean", "rolling"] as const;
type Method = (typeof METHODS)[number];

interface MethodResult {
  eligible: number;
  detections: number;
  anomaliesHit: number;
  falsePositives: number;
  predictableEligible: number;
  predictableFalsePositives: number;
}

export interface ComparisonTable {
  anomalies: number;
  results: Record<Method, MethodResult>;
}

function emptyResult(): MethodResult {
  return { eligible: 0, detections: 0, anomaliesHit: 0, falsePositives: 0, predictableEligible: 0, predictableFalsePositives: 0 };
}

export function compareMethods(fixture: ReturnType<typeof relativeVolumeEquityFixture>): ComparisonTable {
  const { bars, labels } = fixture;
  const engine = createRelativeVolumeEngine({ sessions: RELATIVE_VOLUME_DEFAULT_SETTINGS.sessions, minSessions: RELATIVE_VOLUME_DEFAULT_SETTINGS.minSessions, clock: "auto" });
  const results: Record<Method, MethodResult> = { timeOfDay: emptyResult(), sameSlotMean: emptyResult(), rolling: emptyResult() };
  const anomalyIndices = new Set(labels.anomalyIndices);
  const predictableSlotIndices = new Set(labels.predictableSlotIndices);
  const evaluationIndices = new Set(labels.evaluationIndices);
  for (let index = 0; index < bars.length; index += 1) {
    const reading = engine.onBar(bars[index]);
    if (!evaluationIndices.has(index)) continue;
    const ratios: Record<Method, number | null> = { timeOfDay: reading.rvol, sameSlotMean: reading.slotMeanRatio, rolling: reading.rolling };
    // Readiness is asserted from actual prior observations per key, never from a calendar day number.
    if (METHODS.some((method) => ratios[method] === null)) continue;
    const anomaly = anomalyIndices.has(index);
    const predictable = predictableSlotIndices.has(index);
    for (const method of METHODS) {
      const result = results[method];
      const detected = (ratios[method] as number) >= THRESHOLD;
      result.eligible += 1;
      if (predictable) result.predictableEligible += 1;
      if (detected) result.detections += 1;
      if (anomaly && detected) result.anomaliesHit += 1;
      if (!anomaly && detected) {
        result.falsePositives += 1;
        if (predictable) result.predictableFalsePositives += 1;
      }
    }
  }
  return { anomalies: labels.anomalies.length, results };
}

function pct(numerator: number, denominator: number): string {
  return denominator === 0 ? "n/a" : `${((100 * numerator) / denominator).toFixed(2)}%`;
}

const METHOD_LABELS: Record<Method, string> = {
  timeOfDay: "Time of day (slot median)",
  sameSlotMean: "Same-slot mean",
  rolling: "Rolling 20 mean",
};

export function formatComparison(title: string, table: ComparisonTable): string {
  const lines = [
    `${title} (threshold ${THRESHOLD.toFixed(1)}, ${table.anomalies} anomalies)`,
    "| Method | Eligible bars | Detections | Anomalies hit | Recall | False positives | FP rate | Predictable-slot bars | Predictable-slot FPs | Predictable-slot FP rate |",
    "|---|---|---|---|---|---|---|---|---|---|",
  ];
  for (const method of METHODS) {
    const r = table.results[method];
    lines.push(
      `| ${METHOD_LABELS[method]} | ${r.eligible} | ${r.detections} | ${r.anomaliesHit}/${table.anomalies} | ${pct(r.anomaliesHit, table.anomalies)} | ${r.falsePositives} | ${pct(r.falsePositives, r.eligible - r.anomaliesHit)} | ${r.predictableEligible} | ${r.predictableFalsePositives} | ${pct(r.predictableFalsePositives, r.predictableEligible)} |`,
    );
  }
  return lines.join("\n");
}
